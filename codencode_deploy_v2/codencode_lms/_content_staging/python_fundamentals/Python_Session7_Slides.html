What is Vibe Coding? 🤖

Vibe Coding = using AI to write code by describing what you want in plain English. You focus on WHAT you want to build; AI handles HOW to write the code.

This does not replace programmers — it makes programmers 5–10x more productive. You still need to understand the code to guide, debug, and improve it.
⚡
Before AI (2020)
Googling Stack Overflow for every syntax question. Spending 2 hours on a bug that was a missing colon. Building a todo app took a weekend.
🚀
After AI (now)
Describe your bug in English, get the fix in seconds. Scaffold a full CRUD app in 10 minutes. Spend your time on logic, not syntax.
✅
What AI is GREAT at
Boilerplate code, converting between formats, explaining error messages, writing tests, suggesting architecture, translating between languages.
⚠️
What AI still gets wrong
Complex business logic with many rules, security edge cases, knowing your specific codebase context, and it sometimes confidently gives wrong answers.

Frontend vs Backend — Know the Difference 🌐

Frontend = what the user sees and touches. Backend = the logic and data behind the scenes. Most apps need both — but you do not have to build both yourself.

🖼️ Frontend

  • Everything the user sees in their browser or app
  • Languages: HTML, CSS, JavaScript (React, Vue)
  • Handles: buttons, forms, layout, animations
  • Runs: in the user browser (client-side)
  • Talks to backend: via HTTP requests (fetch/axios)
  • Tool choice: Bolt.new, React, plain HTML/CSS/JS

⚙️ Backend

  • The server — logic, database, authentication
  • Languages: Python (Flask/Django), Node.js, Go
  • Handles: storing data, user auth, business rules
  • Runs: on a server (AWS, Railway, Render, Heroku)
  • Exposes: REST API endpoints that frontend calls
  • Tool choice: Flask + SQLite to learn, FastAPI for production
💡 Python is primarily a backend language. With Flask you build APIs. With requests you call other APIs. With files/databases you store data.
# simple_flask_api.py
# pip install flask
from flask import Flask, jsonify, request

app = Flask(__name__)
todos = []

@app.route("/todos", methods=["GET"])
def get_todos():
    return jsonify(todos)

@app.route("/todos", methods=["POST"])
def add_todo():
    data = request.get_json()
    todos.append(data["task"])
    return jsonify({"status": "added"}), 201

if __name__ == "__main__":
    app.run(debug=True)

# GET  /todos  → returns list
# POST /todos  → adds new item

Prompt Engineering — Talk to AI Like a Senior Dev 🧠

The quality of AI output depends 90% on the quality of your prompt. Bad prompt gives generic garbage. Great prompt gives production-ready code.

The CRAFT framework

  • Context — what are you building? What tech stack?
  • Role — "Act as a senior Python developer"
  • Action — what exactly do you want?
  • Format — "Return only the Python function, no explanation"
  • Test case — give an example input/output

Prompt examples

  • ❌ "Write a login system"
  • ✅ "Write a Flask POST /login that accepts email+password JSON, checks against a users dict, returns JWT on success, 401 on failure. Include error handling."
  • ❌ "Fix my code"
  • ✅ "This function returns None instead of the list. Here is the code: [paste]. Expected output: [example]. Fix only the bug, keep the same structure."

When to use which prompt style

  • Scaffold: "Generate a complete [X] with these requirements: [list]"
  • Debug: "Error: [paste error]. Code: [paste code]. Expected: [describe]. Fix it."
  • Explain: "Explain this code line by line like I am a beginner: [code]"
  • Improve: "Refactor this to be more Pythonic and add type hints: [code]"
  • Test: "Write 5 pytest test cases for this function: [code]"
⚠️ Always review AI code before running it. AI can generate code that looks right but has security holes. Never paste API keys into AI prompts.
💡 Pro tip: Paste full error tracebacks directly into Claude. It solves 90% of common bugs instantly.
