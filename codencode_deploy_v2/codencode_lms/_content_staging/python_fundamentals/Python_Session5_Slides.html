What is OOP? Why Use It? 🤔

What: OOP groups related data and functions together into a single "object".
When: When you have multiple "things" that each have their own data and behaviour — users, bank accounts, products, vehicles.
Why: Without OOP, managing 100 students means 100 separate variable sets. With OOP, one class handles them all.
# before_after_oop.py
# ❌ Without OOP — messy parallel variables
student1_name  = "Ali"
student1_age   = 20
student1_score = 85

student2_name  = "Siti"
student2_age   = 19
student2_score = 92
# 100 students = 300 variables 😱

# ✅ With OOP — clean and scalable
class Student:
    def __init__(self, name, age, score):
        self.name  = name
        self.age   = age
        self.score = score

s1 = Student("Ali",  20, 85)
s2 = Student("Siti", 19, 92)
# 100 students: just 100 Student() calls ✅

4 pillars of OOP

  • Encapsulation — bundle data + methods together
  • Abstraction — hide complexity, show simple interface
  • Inheritance — new class extends an existing one
  • Polymorphism — same method, different behaviour

Real-world OOP everywhere

  • Instagram: User class, Post class, Comment class
  • Banking: Account class, Transaction class
  • Games: Player class, Enemy class, Weapon class
  • Webshop: Product class, Cart class, Order class

Classes & Objects — Blueprint & Instance 🏗️

Class = the blueprint (design). Object = an instance (actual thing). self refers to the specific object being used. __init__ is called automatically when you create an object.
# class_basics.py
class BankAccount:
    """A simple bank account."""

    def __init__(self, owner, balance=0):
        self.owner   = owner   # attribute
        self.balance = balance # attribute

    def deposit(self, amount):
        self.balance += amount
        print(f"✅ Deposited RM{amount}")

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("Insufficient funds!")
        self.balance -= amount

    def __str__(self):
        return f"{self.owner}: RM{self.balance:.2f}"

# Create instances (objects)
ali  = BankAccount("Ali", 1000)
siti = BankAccount("Siti")

ali.deposit(500)       # RM1500
ali.withdraw(200)      # RM1300
print(ali)             # Ali: RM1300.00

Key terms

  • class Name: — define the blueprint
  • __init__(self, ...) — constructor
  • self — the specific object
  • self.name = name — store as attribute
  • obj.method() — call a method
  • __str__ — controls print(obj) output

Inheritance

  • class SavingsAccount(BankAccount):
  • Inherits all methods from BankAccount
  • Add new attributes/methods
  • Override parent methods to change behaviour
  • super().__init__(...) — call parent init
💡 Think: class = cookie cutter. Object = actual cookie. Every cookie is different (different flavour) but same shape (same class).

Inheritance — Extend & Specialise 👪

When: When one thing IS a more specific version of another. SavingsAccount IS a BankAccount. GraduateStudent IS a Student. Car IS a Vehicle.
Why: Inherit all the parent's code for free — only write what's different.
# inheritance.py
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."  # override in subclass

    def __str__(self):
        return f"{self.name} says {self.speak()}"

class Dog(Animal):    # inherits Animal
    def speak(self): return "Woof!"
    def fetch(self):  print("Fetching!")

class Cat(Animal):
    def speak(self): return "Meow!"

d = Dog("Rex")
c = Cat("Whiskers")
print(d)          # Rex says Woof!
print(c)          # Whiskers says Meow!

# @dataclass — less boilerplate
from dataclasses import dataclass

@dataclass
class Student:
    name:  str
    age:   int
    score: float = 0.0

s = Student("Ali", 20, 85.5)
print(s)  # Student(name=Ali, age=20, score=85.5)

Inheritance rules

  • Use when: child IS A parent
  • Child gets all parent methods free
  • Override a method to change behaviour
  • super().__init__() to call parent constructor
  • isinstance(d, Animal) → True for Dog

@dataclass benefits

  • Auto-generates __init__, __str__, __repr__
  • Add type hints: name: str
  • Default values: score: float = 0.0
  • Much less code for simple data classes
  • Use for: Student, Product, Config, Point

👨‍🏫 Teacher Demo: Bank Account System

Full OOP: class, inheritance, methods, validation

# bank_system.py
class Account:
    def __init__(self, owner, balance=0):
        self.owner   = owner
        self.balance = balance
        self.history = []

    def deposit(self, amt):
        if amt <= 0: raise ValueError("Amount must be positive")
        self.balance += amt
        self.history.append(f"+RM{amt}")

    def withdraw(self, amt):
        if amt > self.balance: raise ValueError("Insufficient funds")
        self.balance -= amt
        self.history.append(f"-RM{amt}")

    def statement(self):
        print(f"--- {self.owner} ---")
        for t in self.history: print(f"  {t}")
        print(f"Balance: RM{self.balance:.2f}")

class SavingsAccount(Account):
    def __init__(self, owner, rate=0.03):
        super().__init__(owner)
        self.rate = rate

    def add_interest(self):
        interest = self.balance * self.rate
        self.deposit(round(interest, 2))
