The test for a good function

You can describe what it does in one short sentence with no "and". "Works out the total of a cart" is a function. "Works out the total and prints the receipt and saves the file" is three.

1.1 · Why functions

The same eight lines, in four different places

Definition

Function

A named block of code that takes input, does one job, and usually hands a value back. You write it once and call it by name wherever you need it.

the problem
# in three places in your contact book...
print("=" * 40)
for i, c in enumerate(book, 1):
    print(f"{i}. {c['name']}")
print("=" * 40)

# change the format -> edit 3 places
# forget one -> a bug nobody notices for a month
the fix
def show_book(book):
    """Print every contact as a numbered list."""
    print("=" * 40)
    for i, c in enumerate(book, 1):
        print(f"{i}. {c['name']}")
    print("=" * 40)

# now, everywhere:
show_book(book)
Three things you gain, in order of importance

One place to fix it. Then: you can test it on its own without running the whole program. Then: the calling code reads like the description of what it does, not like the machinery.

The name is the documentation

calculate_total(cart) tells the reader everything. do_it(x) tells them nothing. Verb first, then the thing.

1.2 · def, call, return

Watch a call: values in, one value out

Defining a function runs nothing. Only the call makes the body execute.

the callerarguments going inreturn value coming back
What just happened

—

the code being animated
def area(width, height):
    result = width * height
    return result

a = area(5, 3)
print(a)   # 15

return is not print

print shows a human something. return hands a value to the code. A function that prints instead of returning cannot be used in a calculation.

1.3 · Parameters

Parameters, arguments, and returning more than one thing

Definition

Parameter vs argument

The parameter is the name in the definition — def greet(name). The argument is the actual value you pass in — greet("Aisyah").

returning nothing, one thing, or several
# returns nothing -> None
def greet(name):
    print(f"Hi {name}")

# returns one value
def total(cart):
    return sum(i["price"] * i["qty"] for i in cart)

# returns several — really one tuple
def stats(nums):
    return min(nums), max(nums), sum(nums)/len(nums)

lo, hi, avg = stats([4, 9, 2])
return exits immediately — use it as a guard
def average(nums):
    if not nums:
        return 0        # out now, no crash
    return sum(nums) / len(nums)

# without the guard, an empty list gives
# ZeroDivisionError: division by zero
Session 2's guard clause, now with teeth

In Session 2 the guard just stopped a branch. In a function it can leave entirely, which is what makes the pattern worth having. Handle the empty case, the negative case, the None case at the top — then write the real logic unindented.

before and after
# BEFORE — printing, so unusable elsewhere
def total(cart):
    t = 0
    for i in cart:
        t += i["price"] * i["qty"]
    print(t)          # dead end

# AFTER — returns, so it composes
def total(cart):
    """Total price of every item in the cart."""
    return sum(i["price"] * i["qty"] for i in cart)

print(f"RM {total(cart):.2f}")
print(f"with tax: RM {total(cart) * 1.06:.2f}")

The rule you can apply mechanically

If a function's job is to work something out, it returns. If its job is to show something, it prints. Never both — that is two functions.

2.1 · Scope

A local scope opens on the call and dies on the return

Inside can read outside. Outside can never read inside. That is the whole rule.

global — whole programlocal — only while runninggone
What just happened

—

the code on screen
TAX_RATE = 0.06       # global

def total(price):
    tax = price * TAX_RATE   # reads global
    return price + tax    # tax is local

print(total(100))
print(tax)  # NameError

Why this is a feature

You can name a variable i or total inside a function without caring what the rest of the program called things.

2.2 · Default & keyword arguments

Sensible defaults, and calls that read like English

Definition

Default argument

A value given in the definition that is used when the caller does not supply one — def total(price, rate=0.06).

defaults make the common case short
def total(price, rate=0.06, discount=0):
    """Price after discount, plus tax at rate."""
    net = price * (1 - discount)
    return net * (1 + rate)

total(100)                    # 106.0  — both defaults
total(100, 0.10)              # 110.0  — override rate
total(100, discount=0.2)      # 84.8   — skip rate, name discount
keyword arguments kill the mystery call
# what do these mean? nobody knows
send("Aisyah", True, False, 3)

# self-explanatory, and order stops mattering
send("Aisyah", urgent=True,
     archive=False, retries=3)

The mutable default trap

def add(item, cart=[]) creates the list once, when the function is defined — so every call shares it and the cart keeps growing. Use cart=None then if cart is None: cart = [].

Defaults come last

def f(a, b=1, c=2) is fine; def f(a=1, b) is a SyntaxError — Python would have no way to know which value you meant.

2.3 · Docstrings

Teacher Demo — a function worth reusing

toolkit.py — the shape to copy
"""Small helpers used across the bootcamp projects."""

def ask_number(prompt, minimum=None, maximum=None):
    """Ask until the user types a number inside the range.

    prompt  -- what to show the user
    minimum -- lowest allowed value, or None
    maximum -- highest allowed value, or None
    Returns a float. Never raises.
    """
    while True:
        try:
            value = float(input(prompt))
        except ValueError:
            print("Numbers only."); continue
        if minimum is not None and value < minimum:
            print(f"At least {minimum}."); continue
        if maximum is not None and value > maximum:
            print(f"At most {maximum}."); continue
        return value
Definition

Docstring

A string on the first line of a function that says what it does. help(ask_number) prints it, and every editor shows it when you hover the name.

Notice all three ideas at once

Session 2's try/except for bad input, Session 3's while loop to keep asking, and today's default arguments so the simple call stays simple. This one function is the course so far.

The twenty-line rule

If a function will not fit on one screen, it is doing more than one job. Split it. The number is not sacred — the point is that you can hold the whole thing in your head at once.

3.1 · The call stack

Functions stack up, then unwind

Each call pushes a frame. Each return pops one. When the stack is empty, the program ends.

mainreceiptline_totalwith_tax

This is what a traceback is

When Python crashes it prints the stack — every frame, outermost first. The last line is where it actually broke; the lines above are how it got there.

Read a traceback from the bottom up

Bottom line: the error. Line above: the function and line number that raised it. Keep going up only if that function looks innocent and you need to know who called it with bad data.

3.2 · Modules

One file becomes three

Definition

Module

Any .py file. Import it and you get everything defined inside — functions, constants, classes.

the three import forms
# 1 — the whole module (clearest)
import toolkit
n = toolkit.ask_number("Age? ")

# 2 — just what you need
from toolkit import ask_number, money
n = ask_number("Age? ")

# 3 — with a shorter name
import toolkit as tk
n = tk.ask_number("Age? ")

# from toolkit import *  — never do this.
# You lose track of where names came from.
the line you will see in every Python file
# contacts.py
def main():
    book = load()
    menu(book)

if __name__ == "__main__":
    main()
What that if actually does

__name__ is "__main__" when the file is run, and the module's name when it is imported. So the guard means: run the program if I am the program, but stay quiet if someone is just borrowing my functions.

Circular imports

If a.py imports b.py and b.py imports a.py, Python gives up. The fix is almost always to move the shared thing into a third file that both import.

01Split your contact book into three files: storage.py, contacts.py, main.py.
02storage.py holds save and load. contacts.py holds add, find, show, remove. main.py holds the menu loop only.

main.py — this is all it should contain
from storage import load, save
from contacts import add, find, show
from toolkit import ask_choice

def main():
    """Run the contact book menu until the user quits."""
    book = load()
    while True:
        c = ask_choice("[1] show [2] add [3] find [q] quit: ",
                       ["1", "2", "3", "q"])
        if c == "q": save(book); break
        if c == "1": show(book)
        if c == "2": add(book)
        if c == "3": find(book)

if __name__ == "__main__":
    main()

The mark of a good split

main.py reads like a description of the program, with no logic in it at all. Anyone can open it and understand what the software does in fifteen seconds.
