Same job, two ways

No laptops yet. Look at these two sets of instructions and tell me which one a computer could follow — and what's wrong with the other.

A — how a person says it

Get a cup
Put in some coffee
Add hot water
Stir it a bit
Bring it over

1.1

What is Python?

A language you can almost read out loud

Python was designed to look like plain English. Less punctuation, fewer symbols, fewer ways to get it subtly wrong.

What people build with it

Data analysis and dashboards · machine learning · automation scripts · web backends · anything repetitive you'd rather not do by hand.

Why we teach it first

It's the language of the Machine Learning track you may take next — and the one AI coding assistants write best.

the same task, two languages
// Java
public class Main {
  public static void main(String[] a){
    System.out.println("Hello");
  }
}

# Python
print("Hello")

Five lines of ceremony, or one line that says what it does.

1.3

print() and input() — talking to your program

greet.py
name = input("What's your name? ")
age  = input("How old are you? ")

print("Hello, " + name)
print(f"Next year you'll be {int(age)+1}")
input() always gives you a string f-strings drop values straight in
terminal
$ python greet.py
What's your name? Aisyah
How old are you? 17
Hello, Aisyah
Next year you'll be 18

fWhy f-strings win

"Hi " + name + ", you are " + str(age)
f"Hi {name}, you are {age}"

2.1

Type casting & type()

int()whole numbers

Chops the decimal off — it does not round. int(9.99) → 9

str()text

Needed any time you join a number onto a string the old way.

2.2

The mistakes everyone makes

what goes wrong
age = input("Age? ")   # "17" — a string!
print(age + 1)         # TypeError

# the fix
age = int(input("Age? "))
print(age + 1)         # 18

# and the sneaky one
print("5" + "5")       # "55", not 10
print(5 + 5)           # 10
operators you'll use today
7 + 2    # 9   add
7 - 2    # 5   subtract
7 * 2    # 14  multiply
7 / 2    # 3.5 divide → always float
7 // 2   # 3   floor divide
7 % 2    # 1   remainder
7 ** 2   # 49  power
% is how you test odd/even

3.1

Where your code actually lives

git add . → git commit -m "message" → git push

A commit message says why, not what. "fix BMI rounding" beats "update file".

3.2

Vibe coding — your AI pair, not your replacement

Good uses, from week one

Explaining an error you don't understand · suggesting a better variable name · writing the boring boilerplate · reviewing code you already wrote.

Where it hurts you

Pasting code you can't read · asking for the whole answer before trying · trusting output you haven't run · skipping the error message.

the rule for this course
# After AI gives you code, always:
1. Run it.
2. Read every line.
3. Change one thing on purpose
   and predict what breaks.
4. If you can't explain it,
   you don't own it yet.
ClaudeChatGPTGitHub Copilot

Full treatment in Session 7 — today just set the habit.

3.3

Your workflow, every week from now

01Pull first

git pull before you write anything.

02Work in your week folder

week1/, week2/ … one folder per session.

03Run it often

Don't write 40 lines then run. Run every few lines.

04Commit when it works

Working code is a save point. Take it.

05Push before you close the laptop

If it's not on GitHub, it doesn't exist.

06Stuck 20 min?

Error message → Google → AI → ask in the group. In that order.
