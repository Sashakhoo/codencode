What are classes and objects?

whatIn plain words

A class is a blueprint that describes a kind of thing: what it has (attributes) and what it does (methods). An object is one real thing made from that blueprint. __init__ sets up each new object; self means "this object".

likeEveryday analogy

The class is the recipe for teh tarik; each cup you pour is an object. Every cup follows the same recipe, but one is less sweet and one is iced.

rulesTheory: the key rules

  • class Drink: uses PascalCase names
  • __init__(self, …) runs when you create an object
  • self.name = name stores data on the object
  • Create with Drink("Kopi O", 2.5), with no new keyword

class Drink:
    """A drink on the kopitiam menu."""

    def __init__(self, name: str, price: float, iced: bool = False):
        self.name = name          # attributes: what each drink HAS
        self.price = price
        self.iced = iced

Instance vs class attributes

whatIn plain words

Instance attributes (self.price) belong to one object. Class attributes (SST = 0.06) are written in the class body and shared by every object. Use them for rules, rates and counters that apply to all.

likeEveryday analogy

Each student has their own name and marks (instance), but everyone in the school shares the same school name and term dates (class).

rulesTheory: the key rules

  • Instance: set in __init__ via self.x
  • Class: set in the class body, read as Drink.SST
  • Change a class attribute once and all objects see it
  • Use UPPER_CASE for constants like rates

Three kinds of method

whatIn plain words

Instance methods use one object's data (self). Class methods (@classmethod, cls) are mostly used as alternative ways to create objects. Static methods are helpers that live in the class but need neither.

likeEveryday analogy

A barista making your drink (instance), the shop opening a new branch from a template (class method), and the price-check rule printed on the wall (static).

rulesTheory: the key rules

  • Instance method: def describe(self)
  • @classmethod def from_csv_row(cls, row) returns cls(…)
  • @staticmethod def is_valid_price(p): no self
  • Call class/static methods on the class: Drink.from_csv_row()
syntax at a glance
class Drink:
    def describe(self): ...

    @classmethod
    def from_csv_row(cls, row):
        return cls(row["name"], float(row["price"]))

    @staticmethod
    def is_valid_price(p): ...

Common mistakes

  • Forgetting self as the first parameter: TypeError.
  • Calling an instance method on the class: Drink.describe().

    def __init__(self, name: str, price: float):
        self.name = name
        self.price = price

        return f"{self.name}: RM{self.price:.2f}"

Build: BankAccount class

real lifePrepaid transit card: balance, top-up, tap in

The card in your wallet is a perfect object: it has an owner, a balance and a trip history; it can top up and tap. One class attribute holds the rule shared by every card.

prepaid_card.py
"""A prepaid transit card, like the one in your wallet (fares are made up)."""


class PrepaidCard:
    MIN_BALANCE = 5.00            # same rule for every card
    cards_issued = 0

    def __init__(self, owner: str, balance: float = 0.0):
        self.owner = owner
        self.balance = balance
        self.trips: list[tuple[str, float]] = []
        PrepaidCard.cards_issued += 1

    def top_up(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("top-up must be positive")
        self.balance += amount
        print(f"  + top up RM{amount:.2f} -> RM{self.balance:.2f}")

    def tap(self, station: str, fare: float) -> bool:
        """Pay a fare. Return False (gate stays shut) if balance is too low."""
        if fare > self.balance:
            print(f"  x {station}: not enough balance (RM{self.balance:.2f})")
            return False
        self.balance -= fare
        self.trips.append((station, fare))
        print(f"  ok {station}: -RM{fare:.2f}, left RM{self.balance:.2f}")
        return True

    def needs_top_up(self) -> bool:
        return self.balance < PrepaidCard.MIN_BALANCE


card = PrepaidCard("Aisyah", 10.00)
card.tap("Station A", 3.40)
card.tap("Station B", 4.80)
card.tap("Station C", 5.00)
print("  top up needed?", card.needs_top_up())
card.top_up(20)
card.tap("Station C", 5.00)
print(f"{card.owner}: {len(card.trips)} trips, RM{card.balance:.2f} left")
print("cards issued:", PrepaidCard.cards_issued)

@property: guard your data

whatIn plain words

A property looks like a normal attribute (p.price), but runs a method behind the scenes. Use a setter to check every new value, and a read-only property for values you calculate.

likeEveryday analogy

A bank teller between you and the vault. You still say "withdraw RM50", but the teller checks your balance before handing it over.

rulesTheory: the key rules

  • @property above a method lets you read it like an attribute
  • @price.setter runs on p.price = …
  • Store the real value in self._price
  • No setter means read-only (computed values)

A price that can never go negative

product_property.py
class Product:
    def __init__(self, name: str, price: float):
        self.name = name
        self.price = price            # this line goes through the setter below

    @property
    def price(self) -> float:         # read:  p.price
        return self._price

    @price.setter
    def price(self, value: float) -> None:   # write: p.price = 5
        if value < 0:
            raise ValueError("price cannot be negative")
        self._price = round(value, 2)

    @property
    def price_with_sst(self) -> float:       # computed, read-only
        return round(self._price * 1.06, 2)


p = Product("Kaya Toast", 3.0)
print(p.price, p.price_with_sst)
p.price = 3.456
print(p.price)
try:
    p.price = -2
except ValueError as e:
    print("rejected:", e)

Dunder methods: make objects behave like built-ins

whatIn plain words

Dunder (double-underscore) methods let your objects work with Python's built-in operations: print(), ==, <, len(), sorted(). You write them; Python calls them.

likeEveryday analogy

Teaching a new staff member the shop's manners: how to introduce themselves (__str__), how to compare prices (__lt__), how to count items in a basket (__len__).

rulesTheory: the key rules

  • __str__ → print(), friendly text for users
  • __repr__ → lists and debugger, for developers
  • __eq__ → ==, __lt__ → < and sorted()
  • __len__ → len()
syntax at a glance
class Product:
    def __str__(self):  return f"{self.name}"
    def __repr__(self): return f"Product({self.name!r})"
    def __eq__(self, other): return self.name == other.name
    def __lt__(self, other): return self.price < other.price

Common mistakes

  • Calling p.__str__() yourself. Use str(p) or print(p).
  • Without __repr__, lists show <Product object at 0x…>.

product_dunders.py
class Product:
    def __init__(self, name: str, price: float):
        self.name = name
        self.price = price

    def __str__(self) -> str:              # print(p) -> for users
        return f"{self.name} (RM{self.price:.2f})"

    def __repr__(self) -> str:             # debugger / list display -> for devs
        return f"Product({self.name!r}, {self.price})"

    def __eq__(self, other) -> bool:       # p1 == p2
        return self.name == other.name

    def __lt__(self, other) -> bool:       # p1 < p2, makes sorted() work
        return self.price < other.price


class Cart:
    def __init__(self):
        self.items: list[Product] = []

    def __len__(self) -> int:              # len(cart)
        return len(self.items)


a = Product("Nasi Lemak", 6.5)
b = Product("Roti Canai", 2.5)
print(a)
print([a, b])
print(a == Product("Nasi Lemak", 7.0))
print(sorted([a, b]))
cart = Cart()
cart.items += [a, b]
print(len(cart))

@dataclass: less boilerplate for data-holding classes

whatIn plain words

Most classes that hold data need the same __init__, __repr__ and __eq__. @dataclass writes them for you from a list of typed fields. Add methods as normal.

likeEveryday analogy

A form template: you list the fields (name, price, qty) once, and every copy comes with the boxes already drawn.

rulesTheory: the key rules

  • List fields with types: name: str
  • Defaults go after fields without defaults
  • Lists need field(default_factory=list)
  • frozen=True makes objects read-only

Build: Product & Inventory

real lifeOnline shop catalogue: validation, sale price, sorting

A seller lists products with stock and discounts. The dataclass rejects broken listings, a property computes the sale price, and sorting gives "cheapest first", like a marketplace app.

catalogue.py
"""Online shop catalogue: dataclass + validation + property + sorting."""
from dataclasses import dataclass


@dataclass
class Product:
    name: str
    price: float
    stock: int = 0
    discount: float = 0.0           # 0.20 means 20% off

    def __post_init__(self) -> None:  # runs right after __init__
        if self.price < 0:
            raise ValueError(f"{self.name}: price cannot be negative")
        if not 0 <= self.discount < 1:
            raise ValueError(f"{self.name}: discount must be between 0 and 0.99")

    @property
    def sale_price(self) -> float:
        return round(self.price * (1 - self.discount), 2)

    def __str__(self) -> str:
        tag = f"-{self.discount:.0%}" if self.discount else ""
        sold = "  SOLD OUT" if self.stock == 0 else ""
        return f"{self.name:<20} RM{self.sale_price:>6.2f} {tag:>4}{sold}"


catalogue = [
    Product("Bluetooth Earbuds", 89.00, 12, 0.20),
    Product("Phone Case", 15.90, 0),
    Product("Power Bank 10000mAh", 59.00, 5, 0.10),
    Product("USB-C Cable", 12.00, 40),
]

print("Cheapest first:")
for p in sorted(catalogue, key=lambda p: p.sale_price):
    print(" ", p)

on_sale = [p for p in catalogue if p.stock and p.discount]
print("\nIn stock and on sale:", [p.name for p in on_sale])
print("Stock value: RM", round(sum(p.sale_price * p.stock for p in catalogue), 2))

try:
    Product("Broken listing", -5)
except ValueError as e:
    print("\nRejected:", e)

OOP or functions? Pick the right tool

whatIn plain words

Use a function when data goes in, an answer comes out, and nothing needs remembering. Use a class when some data changes over time and several actions work on it.

likeEveryday analogy

A calculator (function): type, get answer, done. A shopping cart (class): it remembers what's inside while you keep adding and removing.

rulesTheory: the key rules

  • No state to remember → function
  • State + several actions → class
  • Mostly data → dataclass
  • Class with only __init__ + one method → probably a function
syntax at a glance
def myr_to_sgd(amount, rate=0.29):   # function
    return amount * rate

class Cart:                          # class
    def __init__(self): self.items = {}
    def add(self, item, qty=1): ...

Common mistakes

  • Making everything a class "because OOP".
  • Passing the same 6 variables into 10 functions: that's a class waiting to happen.

UML: draw the classes before you code

whatIn plain words

A UML class diagram is a box per class: name on top, attributes in the middle, methods at the bottom. Lines show how classes connect, for example "one Order has many OrderItems".

likeEveryday analogy

An architect's floor plan. You don't start laying bricks before you know where the kitchen and doors go.

rulesTheory: the key rules

  • Top: ClassName · middle: attributes · bottom: methods
  • - private, + public
  • 1..* means one or more
  • Each box becomes a class; each line becomes an attribute

order_uml.py
from dataclasses import dataclass, field


@dataclass
class MenuItem:                     # MenuItem: name, price, category
    name: str
    price: float
    category: str = "food"


@dataclass
class OrderItem:                    # OrderItem: menu_item, qty, line_total()
    menu_item: MenuItem
    qty: int

    def line_total(self) -> float:
        return self.menu_item.price * self.qty


@dataclass
class Order:                        # Order: table, items(1..*), subtotal()
    table: int
    items: list[OrderItem] = field(default_factory=list)

    def add(self, item: MenuItem, qty: int = 1) -> None:
        self.items.append(OrderItem(item, qty))

    def subtotal(self) -> float:
        return sum(i.line_total() for i in self.items)


teh = MenuItem("Teh Tarik", 3.0, "drink")
nasi = MenuItem("Nasi Lemak", 6.5)
order = Order(table=4)
order.add(teh, 2)
order.add(nasi)
print(f"Table {order.table}: {len(order.items)} lines, RM{order.subtotal():.2f}")

From a written brief to classes: nouns, verbs, numbers

whatIn plain words

Read the client's brief and mark it up: nouns become classes or attributes, verbs become methods, numbers become constants. Then draw the UML, then code.

likeEveryday analogy

Reading a recipe: ingredients are the nouns, steps are the verbs, quantities are the numbers. You plan before you cook.

rulesTheory: the key rules

  • Circle nouns → classes / attributes
  • Underline verbs → methods
  • Box numbers → class constants
  • Ask: does this noun need its own class, or is it just a value?
syntax at a glance
# "A car park has 3 bays. Cars enter and leave.
#  RM2 first hour, RM1 each hour after."
class CarPark:
    FIRST_HOUR = 2.0
    NEXT_HOUR = 1.0

# BRIEF: "A car park has 3 bays. Cars enter and leave. Parking costs
#         RM2 for the first hour and RM1 for each hour after. Show free bays."
# nouns -> CarPark, Car (just a plate string)   verbs -> enter, leave, fee
# numbers -> FIRST_HOUR = 2, NEXT_HOUR = 1, bays = 3
import math


class CarPark:
    FIRST_HOUR = 2.0
    NEXT_HOUR = 1.0

    def __init__(self, bays: int):
        self.bays = bays
        self.parked: dict[str, float] = {}       # plate -> entry hour

    def free_bays(self) -> int:
        return self.bays - len(self.parked)

    def enter(self, plate: str, hour: float) -> bool:
        if self.free_bays() == 0:
            return False
        self.parked[plate] = hour
        return True

    def leave(self, plate: str, hour: float) -> float:
        hours = math.ceil(hour - self.parked.pop(plate))
        return self.FIRST_HOUR + max(hours - 1, 0) * self.NEXT_HOUR


park = CarPark(bays=3)
for plate in ["JQA 1234", "WXY 88", "JHB 7"]:
    park.enter(plate, hour=9)
print("free:", park.free_bays(), "| 4th car allowed?", park.enter("BMW 1", 9))
print("JQA 1234 pays RM", park.leave("JQA 1234", hour=12.5))
print("free:", park.free_bays())

A training centre runs courses with limited seats. Students enrol, full courses reject new students, duplicates are blocked, and the manager gets a revenue report. Three classes, each with one job.

tuition_centre.py
"""Tuition centre: courses with limited seats, students enrol, revenue report."""
from dataclasses import dataclass, field


@dataclass
class Student:
    name: str
    phone: str


@dataclass
class Course:
    code: str
    title: str
    fee: float
    seats: int
    enrolled: list[Student] = field(default_factory=list)

    @property
    def seats_left(self) -> int:
        return self.seats - len(self.enrolled)

    def enrol(self, student: Student) -> bool:
        if student in self.enrolled:
            print(f"  {student.name} is already in {self.code}")
            return False
        if self.seats_left == 0:
            print(f"  x {self.code} is full, {student.name} not enrolled")
            return False
        self.enrolled.append(student)
        print(f"  ok {student.name} -> {self.code} ({self.seats_left} seats left)")
        return True


class Centre:
    def __init__(self, name: str):
        self.name = name
        self.courses: dict[str, Course] = {}

    def add_course(self, course: Course) -> None:
        self.courses[course.code] = course

    def revenue(self) -> float:
        return sum(c.fee * len(c.enrolled) for c in self.courses.values())

    def report(self) -> None:
        print(f"\n{self.name}")
        for c in self.courses.values():
            names = ", ".join(s.name for s in c.enrolled) or "-"
            print(f"  {c.code} {c.title:<18} {len(c.enrolled)}/{c.seats}  {names}")
        print(f"  Revenue: RM{self.revenue():,.2f}")


centre = Centre("Codencode Academy JB")
centre.add_course(Course("PY201", "Python Intermediate", 890.0, seats=2))
centre.add_course(Course("ML101", "Machine Learning", 1290.0, seats=3))

aisyah = Student("Aisyah", "012-0000001")
darren = Student("Darren", "012-0000002")
nurin = Student("Nurin", "012-0000003")
py = centre.courses["PY201"]
py.enrol(aisyah)
py.enrol(darren)
py.enrol(nurin)          # full
py.enrol(aisyah)         # duplicate
centre.courses["ML101"].enrol(nurin)
centre.report()
