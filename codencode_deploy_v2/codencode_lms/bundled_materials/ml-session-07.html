1.1 · Bias & variance

The two ways a model can be wrong

Definition

Bias

Error from the model being too simple to capture the pattern. A straight line through a curve is wrong everywhere, and would still be wrong with a million more rows.

Definition

Variance

Error from the model being too sensitive to the particular rows it saw. Change the training sample slightly and it gives a noticeably different answer.

Session 2's overfitting slider, named properly

The underfit end of that slider was high bias. The overfit end was high variance. Everything today is an attack on the variance end without paying for it in bias.

SymptomDiagnosisFix
train score low, test lowhigh biasa richer model, better features
train high, test much lowerhigh variancemore data, regularisation, ensembling
both high, close togetherhealthyship it

A single deep decision tree is the textbook high-variance model

It can memorise the training set perfectly. Move one row and the splits reshuffle. That is exactly the weakness a forest is built to cancel.

see it for yourself, in three lines
from sklearn.tree import DecisionTreeClassifier

for seed in [0, 1, 2]:
    t = DecisionTreeClassifier(random_state=seed).fit(X_tr, y_tr)
    print(seed, round(t.score(X_te, y_te), 3))

# three quite different numbers = variance
1.2 · Bagging

Bootstrap aggregating — many models, one vote

Definition

Bagging

Train the same kind of model many times, each on a random sample of the rows drawn with replacement, then average their predictions (or take the majority vote for classification).

bagging by hand, so it is not magic
import numpy as np
from sklearn.tree import DecisionTreeClassifier

trees, n = [], len(X_tr)
for _ in range(100):
    idx = np.random.choice(n, n, replace=True)   # bootstrap
    trees.append(DecisionTreeClassifier().fit(X_tr[idx], y_tr[idx]))

# majority vote
votes = np.array([t.predict(X_te) for t in trees])
pred  = (votes.mean(axis=0) > 0.5).astype(int)
Why drawing with replacement matters

Each bootstrap sample contains about 63% of the unique rows, some of them repeated. That is what makes the trees different from one another — and different trees are the entire point. Identical trees would average to exactly one tree.

Out-of-bag score — free validation

The ~37% of rows a given tree never saw can score that tree. Average that across the forest and you get a validation estimate without holding anything out. oob_score=True.

1.3 · The forest votes

Each tree is barely better than a coin. The vote is not.

The dice reroll every couple of seconds. Watch how often 1 tree is wrong versus 15.

Random Forest adds one more source of difference
from sklearn.ensemble import (
    RandomForestClassifier)

rf = RandomForestClassifier(
    n_estimators=300,
    max_features="sqrt",   # ← the forest bit
    oob_score=True,
    n_jobs=-1, random_state=42,
).fit(X_tr, y_tr)

max_features is what makes it a forest

Bagging alone gives correlated trees, because every tree picks the same strongest feature first. Letting each split see only a random subset of features forces genuine disagreement.

    print(f"{c:<22} {v:.3f}")

Read importance with suspicion

It measures how much each feature reduced impurity, which is not causation and is biased toward high-cardinality columns. If an ID column tops your list, you have a leak, not an insight.

2.1 · Boosting

Each round fits the error the last one left behind

Bagging trains its models in parallel and averages. Boosting trains them in sequence, each correcting the last.

actual valuethe model so farresidual still unexplained
What just happened

—

Definition

Gradient boosting

Models added one at a time, each trained on the residuals the ensemble has not yet explained, and each added at a small fraction (the learning rate) so no single one dominates.

2.2 · XGBoost

The libraries, and the five parameters that matter

the two you will actually use
# pip install xgboost lightgbm
from xgboost import XGBClassifier

model = XGBClassifier(
    n_estimators=600,       # how many rounds
    learning_rate=0.05,     # how much of each to add
    max_depth=5,            # how complex each tree is
    subsample=0.8,          # rows per round
    colsample_bytree=0.8,   # features per round
    eval_metric="logloss",
    early_stopping_rounds=50,
)
model.fit(X_tr, y_tr, eval_set=[(X_val, y_val)], verbose=False)
ParameterRaise it to…Watch for
n_estimatorsfit more of the signaloverfitting — use early stopping
learning_ratelearn fasterovershooting; lower is safer
max_depthcapture interactions3–8 is almost always right
subsample—0.8 adds useful randomness
early_stopping—needs a validation set, not the test set
The trade-off in one line

Lower learning_rate and more n_estimators almost always beats the reverse. It costs training time and buys accuracy — and early stopping means you do not have to guess the number.

Why this family still wins on tabular data

On spreadsheets — which is most business data — a tuned gradient booster routinely beats a neural network, trains in seconds rather than hours, and needs no scaling. Session 5 is for images, text and sequences; this is for rows and columns.

2.3 · Overfitting

Teacher Demo — beating the Session 4 baseline honestly

the three-way split, and why it exists
from sklearn.model_selection import train_test_split

# 1) hold out a TEST set and do not look at it again
X_rest, X_te, y_rest, y_te = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

# 2) split the rest into train and validation
X_tr, X_val, y_tr, y_val = train_test_split(
    X_rest, y_rest, test_size=0.25, stratify=y_rest, random_state=42)

# validation tunes. test is touched ONCE, at the end.

Early stopping on the test set is cheating

It chooses the number of rounds using the data you are about to report on. The number you then quote is not an estimate of anything — and this is the single most common error in student projects.

how to see the overfit happening
results = model.evals_result()
train = results["validation_0"]["logloss"]
val   = results["validation_1"]["logloss"]

plt.plot(train, label="train")
plt.plot(val,   label="validation")
plt.legend(); plt.xlabel("round")

# train falls forever. validation bottoms out,
# then rises — that turn is where to stop.
Always report the baseline next to the model

DummyClassifier(strategy="most_frequent") on an imbalanced dataset can score 95%. If your boosted model scores 96%, you have not built anything — and Session 4's precision, recall and F1 are the numbers that will say so.

from sklearn.model_selection import GridSearchCV

grid = {"max_depth": [2,4,6,8,10,12],
        "learning_rate": [.01,.03,.1,.3,.6,1]}

gs = GridSearchCV(model, grid, cv=5,
                  scoring="f1", n_jobs=-1)
gs.fit(X_tr, y_tr)
print(gs.best_params_, gs.best_score_)

36 cells × 5 folds = 180 fits

Add one more parameter with four values and it becomes 720. Grid search is exhaustive and it grows multiplicatively — which is exactly why random search usually wins in practice.

3.2 · Pipelines

The leak that inflates almost every student project

the code you have been writing since Session 1
# WRONG — and it looks completely reasonable
scaler = StandardScaler().fit(X)        # fitted on EVERYTHING
X_scaled = scaler.transform(X)

X_tr, X_te, y_tr, y_te = train_test_split(X_scaled, y)

model.fit(X_tr, y_tr)
print(model.score(X_te, y_te))   # optimistic. always.
Definition

Data leakage

Any information from outside the training set reaching the model. The scaler above learned the mean and standard deviation of the test rows — so the test set was never truly unseen.

the fix — and it is not more discipline, it is a Pipeline
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler

pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale",  StandardScaler()),
    ("model",  XGBClassifier()),
])

# now EVERY step refits inside each CV fold
scores = cross_val_score(pipe, X_tr, y_tr, cv=5, scoring="f1")

Where leakage hides, in order of frequency

A scaler or imputer fitted before the split · target encoding computed on all rows · a feature that could only be known after the outcome · duplicate rows straddling the split · a random split on time-series data.

The symptom to recognise

Cross-validation says 0.97 and the test set says 0.78. That gap is almost never bad luck — it is something fitted where it should not have been. A Pipeline makes the mistake structurally impossible rather than merely discouraged.

3.3 · Saving

A model that still works next Tuesday

save the whole pipeline, never just the model
import joblib

joblib.dump(gs.best_estimator_, "model.joblib")

# later, in another file, on another machine
pipe = joblib.load("model.joblib")
pipe.predict(new_rows)   # imputes + scales + predicts

Saving only the model is the classic mistake

The scaler and imputer are part of how predictions are made. Save them separately and somebody will eventually feed raw values to a model that expects scaled ones — silently, and with plausible-looking output.

Also recordWhy
library versionsa pickle from one sklearn may not load in another
the column orderpredictions are silently wrong if it changes
the test scoreso future-you knows whether a retrain helped
the training datedata drifts; models go stale
a model card in six lines of JSON
import json, datetime, sklearn

card = {
    "trained": datetime.date.today().isoformat(),
    "sklearn": sklearn.__version__,
    "features": list(X.columns),
    "params": gs.best_params_,
    "test_f1": float(f1_score(y_te, pipe.predict(X_te))),
}
json.dump(card, open("model_card.json", "w"), indent=2)
This is what makes Session 8 easy

A capstone with a saved pipeline and a model card can be rerun by a stranger. One with a notebook full of cells that must be executed in a particular order cannot — and that is the difference between a project and a demo.

the whole thing, end to end
from sklearn.model_selection import RandomizedSearchCV

params = {
    "model__max_depth":     [3, 4, 5, 6, 8],
    "model__learning_rate": [.01, .03, .05, .1],
    "model__subsample":     [.6, .8, 1.0],
}
# note the model__ prefix — it names the pipeline step

rs = RandomizedSearchCV(pipe, params, n_iter=30,
                        cv=5, scoring="f1", n_jobs=-1,
                        random_state=42)
rs.fit(X_tr, y_tr)

print("cv  ", round(rs.best_score_, 3))
print("test", round(f1_score(y_te, rs.predict(X_te)), 3))

joblib.dump(rs.best_estimator_, "model.joblib")

The two numbers are the deliverable

Cross-validated score and test score, side by side. Close together means you can trust it. Far apart means something leaked — and finding it is worth more than another point of accuracy.

Recap & Summary

What you can do now

M1Bagging & Random Forest

Diagnose bias against variance, and cut variance by averaging many decorrelated trees rather than tuning one.

M2Boosting

Fit each new tree to what is still wrong, control it with the learning rate and early stopping, and always report the baseline beside the score.

M3Tuning & Pipelines

Search hyperparameters with cross-validation, put every transformation inside a Pipeline so nothing leaks, and save the whole pipeline with a model card.

The one line to remember

A crowd of weak, disagreeing models beats one clever one — and a score you cannot reproduce is not a score. Ensembling wins the accuracy; the Pipeline is what makes the number mean something.
