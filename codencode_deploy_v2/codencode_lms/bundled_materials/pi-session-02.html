Imports: using code that already exists

whatIn plain words

A module is just a .py file. import lets you use its functions in your file. Python ships with hundreds of modules (math, csv, datetime). Every file also has a __name__, which tells it whether it was run directly or imported.

likeEveryday analogy

Your kitchen doesn't grow its own rice. You import it from the shop. __main__ is the difference between cooking at home and selling your sambal to others.

rulesTheory: the key rules

  • import math → use math.ceil()
  • from statistics import mean → use mean()
  • import datetime as dt gives a short alias
  • if __name__ == "__main__": runs only when run directly

Your own module: split code into files

whatIn plain words

Any .py file you write can be imported by another file in the same folder. Put reusable functions in one file (the module) and the program that uses them in another.

likeEveryday analogy

A recipe book (module) and the cook (main program). The cook doesn't rewrite the recipe each time; they open the book to the right page.

rulesTheory: the key rules

  • File grading.py → from grading import grade
  • One job per module: grading, files, money…
  • Put a self-test under __main__
  • Don't name files math.py or csv.py: they hide the real ones
syntax at a glance
# grading.py
def grade(mark):
    ...

# report.py (same folder)
from grading import grade
print(grade(88))

Common mistakes

  • Running from a different folder: Python can't find the module.
  • Circular imports: a imports b, and b imports a.

grading.py is the module, report.py uses it

grading.py
"""grading.py: grade helpers you can reuse in any project."""

PASS_MARK = 50


def grade(mark: int) -> str:
    """Return A, B, C or F for a 0-100 mark."""
    if mark >= 80:
        return "A"
    if mark >= 65:
        return "B"
    if mark >= PASS_MARK:
        return "C"
    return "F"


if __name__ == "__main__":
    # self-test: runs only with  python grading.py
    assert grade(85) == "A" and grade(49) == "F"
    print("grading.py self-test ok")
report.py
"""report.py: lives in the SAME folder as grading.py."""
from grading import PASS_MARK, grade

marks = {"Aisyah": 88, "Darren": 47, "Nurin": 75}
for name, mark in marks.items():
    print(f"{name:<7} {mark:>3}  {grade(mark)}")
print("pass mark is", PASS_MARK)

Packages: a folder of modules

whatIn plain words

When you have many modules, group them in a folder with an __init__.py file. That folder is a package, and you import with dots: utils.money.

likeEveryday analogy

Modules are single books; a package is a bookshelf with labelled sections. __init__.py is the label that says "this shelf belongs to utils".

rulesTheory: the key rules

  • Folder + __init__.py = package
  • Dots follow folders: from utils.money import rm
  • __init__.py can re-export the most used names
  • Run your program from the folder above the package

Build: your utils package

real lifemymoney.py: one money module, reused in every project

Every Malaysian invoice, POS and quotation needs the same helpers: format RM, add SST, round cash to 5 sen. Write them once as a module with a self-test, then import them anywhere.

mymoney.py
"""mymoney.py: money helpers for Malaysian prices. Reuse in every project."""

SST_RATE = 0.06


def rm(amount: float) -> str:
    """Format as ringgit, e.g. RM1,234.50."""
    return f"RM{amount:,.2f}"


def add_sst(amount: float, rate: float = SST_RATE) -> float:
    """Add SST (default 6%)."""
    return round(amount * (1 + rate), 2)


def cash_round(amount: float) -> float:
    """Round to the nearest 5 sen for cash payments."""
    return round(round(amount / 0.05) * 0.05, 2)


if __name__ == "__main__":
    assert rm(1234.5) == "RM1,234.50"
    assert add_sst(100) == 106.0
    assert cash_round(10.62) == 10.60
    assert cash_round(10.63) == 10.65
    print("mymoney: all checks passed")
invoice.py
"""invoice.py: a small invoice that reuses mymoney.py."""
from mymoney import add_sst, cash_round, rm

items = [("Website hosting (1 yr)", 360.00), ("Domain .my", 85.00),
         ("Setup fee", 150.00)]

subtotal = sum(price for _, price in items)
total = add_sst(subtotal)
for name, price in items:
    print(f"{name:<24}{rm(price):>12}")
print(f"{'Subtotal':<24}{rm(subtotal):>12}")
print(f"{'SST 6%':<24}{rm(total - subtotal):>12}")
print(f"{'TOTAL':<24}{rm(total):>12}")
print(f"{'Cash payment':<24}{rm(cash_round(total)):>12}")

pathlib and with: open files safely

whatIn plain words

pathlib treats a file path as an object you can ask questions (exists? name? extension?). The with statement opens a file and always closes it, even if your code crashes halfway.

likeEveryday analogy

with is a door that closes itself behind you, so you never leave the shop unlocked overnight.

rulesTheory: the key rules

  • Path("data") / "marks.csv" joins paths on any OS
  • .exists() .name .stem .suffix .glob("*.csv")
  • with path.open("w") as f: closes automatically
  • Always pass encoding="utf-8" for BM/中文 text

Make a folder, write files, list them back

receipts.py
from pathlib import Path

folder = Path("receipts")
folder.mkdir(exist_ok=True)                  # create if missing

# write three small files
for month in ["2026-08", "2026-09", "2026-10"]:
    path = folder / f"{month}.txt"           # '/' joins paths on any OS
    with path.open("w", encoding="utf-8") as f:
        f.write(f"Receipts for {month}\n")
# the file is closed here, even if an error happened inside 'with'

for path in sorted(folder.glob("*.txt")):
    print(path.name, "|", path.stem, "|", path.suffix, "|",
          path.read_text(encoding="utf-8").strip())

print("exists?", (folder / "2026-10.txt").exists())

CSV: the format every app can export

whatIn plain words

A CSV is a plain-text table: one row per line, commas between columns. Excel, Google Sheets, banks and e-wallets all export it. csv.DictReader turns each row into a dict using the header row.

likeEveryday analogy

A CSV is a spreadsheet with the formatting removed. It looks plain, but every program in the world can read it.

rulesTheory: the key rules

  • DictReader: rows become dicts with the header as keys
  • Every value is a string: cast with int() or float()
  • Open with newline="" to avoid blank lines on Windows
  • DictWriter + writeheader() + writerows()
syntax at a glance
import csv
with open("marks.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["name"], int(row["mark"]))

Common mistakes

  • Comparing "9" > "10" as strings gives True. Cast first.
  • Splitting lines on "," by hand breaks on names like "Tan, Ah Kow".

Write a CSV, read it back, filter to a new file

marks_csv.py
import csv
from pathlib import Path

# 1. write a CSV (normally you'd get this from Excel / Google Sheets)
rows = [{"name": "Aisyah", "class": "5A", "mark": 88},
        {"name": "Darren", "class": "5B", "mark": 47},
        {"name": "Nurin", "class": "5A", "mark": 75}]
with open("marks.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "class", "mark"])
    writer.writeheader()
    writer.writerows(rows)

# 2. read it back: every value comes back as a STRING
with open("marks.csv", newline="", encoding="utf-8") as f:
    data = list(csv.DictReader(f))
print(data[0])
print(type(data[0]["mark"]))

# 3. filter and write a new file
passed = [r for r in data if int(r["mark"]) >= 50]
with open("passed.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "mark"], extrasaction="ignore")
    writer.writeheader()
    writer.writerows(passed)
print(Path("passed.csv").read_text(encoding="utf-8"))

JSON: saving Python data as text

whatIn plain words

JSON stores nested data (dicts and lists) as text. It's how APIs, web apps and config files share data. json.dump writes Python to a file; json.load reads it back.

likeEveryday analogy

Packing a bento box: JSON is the standard container shape, so any lunch box (program) can open it and find the rice where it expects.

rulesTheory: the key rules

  • dict → object, list → array, True → true, None → null
  • json.dump(obj, f, indent=2) writes a readable file
  • json.load(f) reads it back as dicts and lists
  • ensure_ascii=False keeps 中文 readable

Build: marks CSV → JSON report

real lifeExpense tracker: bank CSV in, monthly JSON summary out

Your bank and e-wallet apps export transactions as CSV. This script totals spending by category and saves a JSON summary that a dashboard or website could read.

expense_report.py
"""Monthly expense tracker: CSV in -> JSON summary out."""
import csv
import json
from collections import defaultdict
from pathlib import Path

DATA = Path("expenses.csv")

# 1. sample data: in real life, export this from your bank or e-wallet app
DATA.write_text(
    "date,category,amount\n"
    "2026-10-01,Food,12.50\n"
    "2026-10-01,Transport,4.20\n"
    "2026-10-03,Food,28.00\n"
    "2026-10-05,Bills,129.00\n"
    "2026-10-07,Transport,15.80\n"
    "2026-10-09,Food,9.90\n",
    encoding="utf-8",
)

# 2. read and total by category
totals: dict[str, float] = defaultdict(float)
with DATA.open(newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        totals[row["category"]] += float(row["amount"])

summary = {
    "month": "2026-10",
    "total": round(sum(totals.values()), 2),
    "biggest": max(totals, key=totals.get),
    "by_category": {k: round(v, 2) for k, v in sorted(totals.items())},
}

# 3. save the report
out = Path("summary.json")
with out.open("w", encoding="utf-8") as f:
    json.dump(summary, f, indent=2)
print(out.read_text(encoding="utf-8"))

try/except: plan for things going wrong

whatIn plain words

Some errors are expected: a user types "dua puluh" instead of 20, a file is missing, the internet drops. try runs risky code; except catches a specific error so the program carries on instead of crashing.

likeEveryday analogy

A safety net under a trapeze act. The act (try) goes on as normal; the net (except) only matters when someone falls.

rulesTheory: the key rules

  • Catch specific errors: ValueError, KeyError, FileNotFoundError
  • else runs only if no error happened
  • finally always runs (cleanup)
  • Never use a bare except:, because it hides real bugs

Turning messy user input into numbers safely

safe_input.py
def to_number(text: str) -> float | None:
    """Turn user input into a number, or None if it isn't one."""
    try:
        value = float(text.replace("RM", "").replace(",", "").strip())
    except ValueError:
        print(f"  '{text}' is not a number")
        return None
    else:
        print(f"  '{text}' -> {value}")      # runs only if no error
        return value
    finally:
        pass                                  # always runs (close files, etc.)


for raw in ["12.50", "RM 1,250", "dua puluh", ""]:
    to_number(raw)

# catching a different error type
menu = {"teh": 3.0}
try:
    print(menu["kopi"])
except KeyError as e:
    print("  not on the menu:", e)

Custom exceptions and logging: say exactly what went wrong

whatIn plain words

You can raise your own errors with clear names like InvalidMarkError. logging replaces print() for messages about what your program is doing: it adds time and level, and can write to a file.

likeEveryday analogy

A custom exception is a specific warning light ("oil low") instead of a generic "something is wrong". Logging is the car's trip recorder.

rulesTheory: the key rules

  • class MyError(ValueError): inherit a built-in error
  • raise MyError("reason") when the rule is broken
  • Levels: DEBUG < INFO < WARNING < ERROR
  • logging.basicConfig(filename="app.log") logs to a file
syntax at a glance
class InvalidMarkError(ValueError):
    """Mark outside 0-100."""

raise InvalidMarkError("105 is outside 0-100")

log = logging.getLogger(__name__)
log.warning("line %d skipped", 4)

Common mistakes

  • Catching ValueError before your own subclass: the subclass handler never runs.
  • Logging passwords or full IC numbers.

Our own error type plus logging levels

marks_log.py
import logging

logging.basicConfig(level=logging.INFO,
                    format="%(asctime)s %(levelname)-7s %(message)s",
                    datefmt="%H:%M:%S")
log = logging.getLogger(__name__)


class InvalidMarkError(ValueError):
    """Mark is missing or outside 0-100."""


def parse_mark(raw: str) -> int:
    mark = int(raw)                              # may raise ValueError
    if not 0 <= mark <= 100:
        raise InvalidMarkError(f"{mark} is outside 0-100")
    return mark


for raw in ["88", "105", "abc", "60"]:
    try:
        log.info("parsed %d", parse_mark(raw))
    except InvalidMarkError as e:              # our own error, checked first
        log.warning("out of range: %s", e)
    except ValueError:
        log.error("not a number: %r", raw)

Debugging: read the traceback from the bottom up

whatIn plain words

When Python crashes it prints a traceback: the trail of function calls that led to the error. The last line says what went wrong; the line above it says where. The VS Code debugger lets you pause and inspect values.

likeEveryday analogy

A traceback is like the receipts in your wallet after a night out: the last one shows where the money ran out, and the ones before show how you got there.

rulesTheory: the key rules

  • Read the last line first: error type + message
  • Then find the first line in YOUR file above it
  • F9 breakpoint · F5 run · F10 step over
  • Fix the cause, not the symptom

real lifeRegistration import that never crashes on bad rows

A Google Form export has typos: letters in phone numbers, missing names, "abc" for age. This importer keeps the good rows, logs every bad one with its line number, and never shows a traceback.

import_students.py
"""Import student registrations safely: skip bad rows and log why."""
import csv
import io
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)-7s %(message)s")
log = logging.getLogger("import")


class InvalidRowError(ValueError):
    """A row that cannot be imported."""


RAW = io.StringIO(               # pretend this came from a Google Form export
    "name,phone,age\n"
    "Aisyah,012-345 6789,24\n"
    "Darren,01x-555,31\n"
    ",0198765432,19\n"
    "Nurin,0171112233,abc\n"
    "Tan,013-444 5566,45\n"
)


def parse(row: dict[str, str]) -> dict:
    name = row["name"].strip()
    if not name:
        raise InvalidRowError("missing name")
    phone = row["phone"].replace("-", "").replace(" ", "")
    if not (phone.isdigit() and phone.startswith("01") and 10 <= len(phone) <= 11):
        raise InvalidRowError(f"bad phone {row['phone']!r}")
    try:
        age = int(row["age"])
    except ValueError:
        raise InvalidRowError(f"age is not a number: {row['age']!r}") from None
    return {"name": name, "phone": "+6" + phone, "age": age}


good = []
for line_no, row in enumerate(csv.DictReader(RAW), start=2):
    try:
        good.append(parse(row))
    except InvalidRowError as e:
        log.warning("line %d skipped: %s", line_no, e)

log.info("imported %d rows", len(good))
for person in good:
    print(person)
