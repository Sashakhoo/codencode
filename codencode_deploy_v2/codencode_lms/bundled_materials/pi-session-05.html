What is an API?

whatIn plain words

An API is a door into someone else's program over the internet. Your code sends an HTTP request ("GET me today's MYR rates") to a URL, and the server sends back a response: a status code plus data, usually JSON.

likeEveryday analogy

Ordering through the kopitiam window: you say what you want using the menu's words (request), and you get your drink plus a receipt that says whether it went OK (status code).

rulesTheory: the key rules

  • GET read · POST create · PUT update · DELETE remove
  • URL = host + path (endpoint) + ?query=params
  • 2xx OK · 4xx your mistake · 5xx their problem
  • Most APIs reply in JSON

print("url    :", req.url)

print("host   :", parts.netloc, "| path:", parts.path, "| query:", parts.query)
print("same query by hand:", urlencode({"from": "MYR", "to": "USD,SGD"}))

# Status codes you will meet
for code in [200, 201, 400, 401, 404, 429, 500]:
    s = HTTPStatus(code)
    print(f"  {code} {s.phrase:<22} {'OK' if code < 400 else 'problem'}")

requests: talk to an API in three lines

whatIn plain words

The requests library sends HTTP requests for you. Pass params= for the query, always set a timeout=, call raise_for_status() to turn errors into exceptions, and .json() to get a Python dict.

likeEveryday analogy

A reliable runner you send to the shop: tell them exactly what to buy (params), how long to wait before giving up (timeout), and to come back and report if the shop was shut (raise_for_status).

rulesTheory: the key rules

  • requests.get(url, params={…}, timeout=10)
  • resp.raise_for_status() raises on 4xx/5xx
  • resp.json() → dict / list
  • Catch requests.RequestException for any network problem
syntax at a glance
resp = requests.get(URL, params={"from": "MYR"}, timeout=10)
resp.raise_for_status()
data = resp.json()
rate = data["rates"]["USD"]

Common mistakes

  • No timeout: a slow server freezes your program forever.
  • Gluing ?from=…&to=… by hand instead of params=.

Live currency rates, with a fallback when offline

rates.py
import requests

URL = "https://api.frankfurter.app/latest"


def get_rates(base: str, targets: list[str]) -> dict[str, float]:
    """Return {currency: rate} for 1 unit of base. Raises on failure."""
    resp = requests.get(URL, params={"from": base, "to": ",".join(targets)},
                        timeout=10)
    resp.raise_for_status()                 # 4xx/5xx -> HTTPError
    data = resp.json()                      # JSON text -> Python dict
    return data["rates"]


try:
    rates = get_rates("MYR", ["USD", "SGD", "CNY"])
    source = "live"
except requests.RequestException as e:      # no internet, timeout, bad status
    print("API unavailable:", type(e).__name__, "- using sample rates")
    rates = {"USD": 0.21, "SGD": 0.29, "CNY": 1.53}   # illustrative only
    source = "sample"

amount = 250.00
for cur, rate in rates.items():
    print(f"RM{amount:.2f} = {cur} {amount * rate:,.2f}   ({source})")

API keys belong in .env, never in your code

whatIn plain words

Many APIs need a secret API key. Put it in a .env file on your laptop, block that file in .gitignore, and read it with os.getenv(). Commit a .env.example with blank values so others know what to set.

likeEveryday analogy

Your house key stays in your pocket (.env). You give friends a note saying "you'll need a key for the front door" (.env.example), not a copy of the key.

rulesTheory: the key rules

  • pip install python-dotenv, then load_dotenv()
  • os.getenv("KEY", default) reads a value
  • .env in .gitignore, .env.example committed
  • Leaked a key? Revoke it now; deleting the commit isn't enough

Build: MYR currency converter CLI

real lifeUmbrella or not? A live 3-day forecast for Johor Bahru

Open-Meteo is a free weather API with no key. The script asks for JB's rain chance and temperature and turns the numbers into plain advice. When the internet is down it uses sample data instead of crashing.

umbrella.py
"""Should I bring an umbrella? 3-day forecast for Johor Bahru.
Uses Open-Meteo: free, no API key needed."""
import requests

URL = "https://api.open-meteo.com/v1/forecast"
PARAMS = {
    "latitude": 1.4927, "longitude": 103.7414,          # Johor Bahru
    "daily": "precipitation_probability_max,temperature_2m_max",
    "timezone": "Asia/Kuala_Lumpur",
    "forecast_days": 3,
}
SAMPLE = {"daily": {                                   # used when offline
    "time": ["2026-10-21", "2026-10-22", "2026-10-23"],
    "precipitation_probability_max": [80, 35, 60],
    "temperature_2m_max": [31.2, 32.4, 30.8]}}


def get_forecast() -> tuple[dict, str]:
    try:
        resp = requests.get(URL, params=PARAMS, timeout=10)
        resp.raise_for_status()
        return resp.json(), "live"
    except requests.RequestException as e:
        return SAMPLE, f"sample data ({type(e).__name__})"


def advice(rain_chance: int) -> str:
    if rain_chance >= 70:
        return "bring an umbrella"
    if rain_chance >= 40:
        return "maybe pack a small umbrella"
    return "no umbrella needed"


data, source = get_forecast()
daily = data["daily"]
print(f"Johor Bahru forecast - {source}")
for day, rain, temp in zip(daily["time"], daily["precipitation_probability_max"],
                           daily["temperature_2m_max"]):
    print(f"  {day}  rain {rain:>3}%  max {temp:.1f}C  -> {advice(rain)}")

pandas: a spreadsheet you can program

whatIn plain words

A DataFrame is a table with named columns, like a sheet in Excel. pandas lets you load it, look at it, filter rows and add columns, a whole column at a time instead of looping row by row.

likeEveryday analogy

Excel with superpowers: instead of dragging a formula down 10,000 rows, you write one line and it applies to the whole column.

rulesTheory: the key rules

  • pd.read_csv("file.csv") or pd.DataFrame({…})
  • df.head() · df.info() · df.describe() to explore
  • Filter: df[df["qty"] >= 3]; combine with & and |
  • New column: df["total"] = df["qty"] * df["price"]
syntax at a glance
import pandas as pd
df = pd.read_csv("sales.csv")
jb = df[(df["branch"] == "JB") & (df["qty"] >= 3)]
df["total"] = df["qty"] * df["price"]

Common mistakes

  • df[df.qty > 2 and df.branch == "JB"]: use & with brackets.
  • Looping with for over rows: slow and long.

groupby: split, apply, combine

whatIn plain words

groupby answers "per" questions: revenue per branch, sales per month. It splits rows into groups, applies a calculation (sum, mean, count) to each, and combines the results into a small table.

likeEveryday analogy

Counting the day's takings: put the receipts into one pile per stall (split), add up each pile (apply), and write one line per stall in the book (combine).

rulesTheory: the key rules

  • df.groupby("branch")["total"].sum()
  • .agg(["sum", "mean", "count"]) for several at once
  • pivot_table(index=, columns=, values=) for a 2-D table
  • .sort_values(ascending=False) for best first

Clean the data before you trust the numbers

whatIn plain words

Real exports are messy: extra spaces, mixed capitals, "RM 3.00" as text, duplicate rows, missing values, dates in dd/mm/yyyy. Clean them first, or every total you calculate is wrong.

likeEveryday analogy

Washing vegetables before cooking. Skip it and the dish looks fine, but it isn't.

rulesTheory: the key rules

  • .str.strip().str.title() → same spelling
  • .str.replace("RM", "").astype(float) → numbers
  • pd.to_datetime(…, dayfirst=True) for Malaysian dates
  • dropna() then drop_duplicates()
syntax at a glance
df["item"] = df["item"].str.strip().str.title()
df["price"] = df["price"].str.replace("RM", "").astype(float)
df["date"] = pd.to_datetime(df["date"], dayfirst=True)
df = df.dropna().drop_duplicates()

Common mistakes

  • Forgetting dayfirst=True: 01/09 becomes 9 January.
  • Cleaning the original DataFrame in place, so you can't compare before/after.

Five cleaning steps, before and after

clean_sales.py
import pandas as pd

raw = pd.DataFrame({
    "date":  ["01/09/2026", "01/09/2026", "02/09/2026", "02/09/2026", "03/09/2026"],
    "item":  [" teh tarik", "Teh Tarik ", "NASI LEMAK", "nasi lemak", None],
    "price": ["RM 3.00", "3", "RM6.50", "RM6.50", "RM 2.50"],
    "qty":   [2, 2, 1, 1, 3],
})
print("BEFORE"); print(raw); print()


def clean(df: pd.DataFrame) -> pd.DataFrame:
    """Return a cleaned copy of raw sales data."""
    out = df.copy()
    out = out.dropna(subset=["item"])                         # 1 missing item
    out["item"] = out["item"].str.strip().str.title()         # 2 same spelling
    out["price"] = (out["price"].str.replace("RM", "")        # 3 text -> number
                    .str.strip().astype(float))
    out["date"] = pd.to_datetime(out["date"], dayfirst=True)  # 4 dd/mm/yyyy
    return out.drop_duplicates().reset_index(drop=True)       # 5 duplicates


clean_df = clean(raw)
print("AFTER"); print(clean_df)
print("\nrows:", len(raw), "->", len(clean_df), "| price type:", clean_df["price"].dtype)

Build: monthly sales report

real lifeKopitiam sales report: messy export to business answers

The POS exports three months of sales with messy spelling and prices. The owner wants to know: revenue per month per branch, the best sellers, and whether sales are growing.

sales_report.py
"""Kopitiam sales report: messy export -> clean data -> answers."""
import pandas as pd

raw = pd.DataFrame({
    "date": ["01/07/2026", "15/07/2026", "03/08/2026", "18/08/2026", "02/09/2026",
             "20/09/2026", "21/09/2026", "21/09/2026"],
    "branch": ["JB", "KL", "JB", "KL", "JB", "KL", "JB", "JB"],
    "item": ["teh tarik", "Nasi Lemak", "Teh Tarik ", "kaya toast", "NASI LEMAK",
             "Teh Tarik", "Kaya Toast", "Kaya Toast"],
    "qty": [120, 80, 150, 95, 160, 110, 70, 70],
    "price": ["RM3.00", "6.50", "RM 3.00", "3.00", "RM6.50", "3", "3.00", "3.00"],
})

# 1. clean
df = raw.copy()
df["item"] = df["item"].str.strip().str.title()
df["price"] = df["price"].str.replace("RM", "").str.strip().astype(float)
df["date"] = pd.to_datetime(df["date"], dayfirst=True)
df = df.drop_duplicates()
df["revenue"] = df["qty"] * df["price"]

# 2. answer business questions
monthly = df.pivot_table(index=df["date"].dt.strftime("%Y-%m"), columns="branch",
                         values="revenue", aggfunc="sum", fill_value=0)
best = df.groupby("item")["revenue"].sum().sort_values(ascending=False)
growth = monthly.sum(axis=1).pct_change().mul(100).round(1)

print("Monthly revenue (RM):"); print(monthly, "\n")
print("Best sellers (RM):"); print(best, "\n")
print("Month-on-month growth (%):"); print(growth.dropna())
print(f"\nDuplicates removed: {len(raw) - len(df)}")

A chart should say one thing clearly

whatIn plain words

matplotlib draws charts from your data. A good chart answers one question: its title states the answer, the axes have labels and units, and nothing distracts from the point.

likeEveryday analogy

A newspaper headline: "JB sales up 73%" is better than "Sales data Q3". The reader gets the point before reading the numbers.

rulesTheory: the key rules

  • bar compare groups · line trend over time · scatter relationship
  • Title = the takeaway, not just the topic
  • Label both axes, with units (RM, month)
  • fig.savefig("chart.png", dpi=120) for reports

A grouped bar chart that states its point

import matplotlib
matplotlib.use("Agg")                 # draw to a file (remove to use plt.show())
import matplotlib.pyplot as plt

months = ["Jul", "Aug", "Sep"]
jb = [3200, 3900, 5550]
kl = [2900, 2600, 3150]

fig, ax = plt.subplots(figsize=(7, 4))
x = range(len(months))
ax.bar([i - 0.2 for i in x], jb, width=0.4, label="JB", color="#00dcb4")
ax.bar([i + 0.2 for i in x], kl, width=0.4, label="KL", color="#58a6ff")

ax.set_xlabel("Month (2026)")
ax.set_ylabel("Revenue (RM)")
ax.legend(title="Branch")
ax.spines[["top", "right"]].set_visible(False)
fig.tight_layout()
fig.savefig("monthly_revenue.png", dpi=120)
print("saved monthly_revenue.png")

from datetime import date
from pathlib import Path

import pandas as pd       # Excel export also needs: pip install openpyxl

                   "qty": [380, 240, 165], "revenue": [1140.0, 1560.0, 495.0]})

                        "value": [df["revenue"].sum(), df["qty"].sum()]})

out.mkdir(exist_ok=True)
stamp = f"{date(2026, 10, 21):%Y-%m-%d}"          # use date.today() in real life

df.to_csv(out / f"sales_{stamp}.csv", index=False)              # any system
df.to_json(out / f"sales_{stamp}.json", orient="records", indent=2)  # web apps
with pd.ExcelWriter(out / f"sales_{stamp}.xlsx") as xw:         # your boss
    summary.to_excel(xw, sheet_name="Summary", index=False)
    df.to_excel(xw, sheet_name="By item", index=False)

for f in sorted(out.iterdir()):
    print(f"{f.name:<24} {f.stat().st_size:>6} bytes")
print(pd.read_excel(out / f"sales_{stamp}.xlsx", sheet_name="Summary"))

Fetch rates → SQLite → pandas → % change

pipeline.py
"""Pipeline: fetch (API) -> store (SQLite) -> analyse (pandas) -> report."""
import sqlite3

import pandas as pd
import requests

URL = "https://api.frankfurter.app/2026-10-01..2026-10-07"
SAMPLE = {"rates": {                       # used when there is no internet
    "2026-10-01": {"USD": 0.2370, "SGD": 0.3060},
    "2026-10-02": {"USD": 0.2375, "SGD": 0.3065},
    "2026-10-05": {"USD": 0.2381, "SGD": 0.3071},
    "2026-10-06": {"USD": 0.2378, "SGD": 0.3069},
    "2026-10-07": {"USD": 0.2386, "SGD": 0.3074}}}


def fetch() -> dict:
    try:
        r = requests.get(URL, params={"from": "MYR", "to": "USD,SGD"}, timeout=10)
        r.raise_for_status()
        return r.json()
    except requests.RequestException:
        print("offline: using sample rates")
        return SAMPLE


def store(conn: sqlite3.Connection, data: dict) -> int:
    conn.execute("CREATE TABLE IF NOT EXISTS rates "
                 "(day TEXT, currency TEXT, rate REAL, UNIQUE(day, currency))")
    rows = [(d, c, r) for d, rates in data["rates"].items() for c, r in rates.items()]
    before = conn.total_changes
    conn.executemany("INSERT OR IGNORE INTO rates VALUES (?, ?, ?)", rows)
    conn.commit()
    return conn.total_changes - before


conn = sqlite3.connect("rates.db")
print("new rows:", store(conn, fetch()))
df = pd.read_sql("SELECT * FROM rates", conn).pivot(index="day",
                                                    columns="currency", values="rate")
print(df)
change = (df.iloc[-1] / df.iloc[0] - 1) * 100
print("\nMYR change over the period (%):"); print(change.round(2))

real lifePersonal finance: 3 months of spending, a chart and an Excel report

You track spending by category. The script builds a stacked chart against your budget line, flags the months you overspent, and saves an Excel file for your records.

spending.py
"""Personal finance: 3 months of spending -> chart + Excel report."""
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import pandas as pd

spend = pd.DataFrame({
    "month": ["Aug"] * 4 + ["Sep"] * 4 + ["Oct"] * 4,
    "category": ["Food", "Transport", "Bills", "Fun"] * 3,
    "amount": [620, 210, 340, 150, 700, 190, 345, 320, 590, 240, 350, 410],
})
table = spend.pivot_table(index="month", columns="category", values="amount",
                          aggfunc="sum").reindex(["Aug", "Sep", "Oct"])
budget = 1400

ax = table.plot(kind="bar", stacked=True, figsize=(7, 4), rot=0,
                color=["#00dcb4", "#58a6ff", "#f0b429", "#ff6f91"])
ax.axhline(budget, color="#333333", linestyle="--", linewidth=1)
ax.text(2.45, budget + 20, f"budget RM{budget}", ha="right", fontsize=9)
ax.set_title("'Fun' spending nearly tripled since August")
ax.set_xlabel("Month (2026)")
ax.set_ylabel("Spent (RM)")
ax.legend(title="Category", bbox_to_anchor=(1, 1), loc="upper left")
plt.tight_layout()
plt.savefig("spending.png", dpi=120)

totals = table.sum(axis=1)
print(table, "\n")
for month, total in totals.items():
    flag = "OVER" if total > budget else "ok"
    print(f"{month}: RM{total:,.0f}  {flag}")
table.to_excel("spending.xlsx")
print("saved spending.png and spending.xlsx")
