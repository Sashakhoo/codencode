1.1 · The neuron

One neuron is a weighted sum and a squash

Definition

Neuron

A unit that multiplies each input by a weight, adds them up with a bias, and passes the total through an activation function.

z = w₁x₁ + w₂x₂ + … + bthe weighted sum — a linear model, nothing more
a = f(z)the activation — this is what makes it non-linear
Why the activation is the whole trick

Without f, stacking layers is pointless: a linear function of a linear function is still linear, so a hundred layers would collapse into one. The activation is what lets depth buy you anything.

one neuron, in four lines of numpy
import numpy as np

x = np.array([0.5, 0.8, 0.2])   # inputs
w = np.array([0.4, -0.6, 0.9])  # weights (learned)
b = 0.1                             # bias (learned)

z = np.dot(w, x) + b
a = max(0, z)                    # ReLU

print(z, a)
# -0.1  0     ← this neuron stays silent

That is genuinely all of it

A network with a million parameters is this exact operation, repeated. Nothing more complicated is happening — there is just a great deal of it.

1.2 · Forward & backward

Signals go forward. Corrections come back.

One full loop of the animation is one training step on one batch.

forward pass — data flowing inbackpropagation — error flowing back
4 → 6 → 6 → 2 · 72 weights
Definition

Forward propagation

Feeding an input through every layer in turn, each neuron computing its weighted sum and activation, until a prediction comes out.

Definition

Backpropagation

Comparing the prediction to the truth, then using the chain rule to work out how much each weight contributed to the error — and nudging every one in the direction that would have reduced it.

One cycle = one training step

Forward, compare, backward, nudge. Repeat a few thousand times. Training is nothing but that loop, and the nudge size is the learning rate you met in Session 3.

1.3 · Backpropagation

What backprop is actually computing

The question it answers

"If I nudged this one weight up slightly, would the error go up or down, and by how much?" That is a partial derivative, and backprop computes it for every weight at once — efficiently, by reusing work from layer to layer.

w := w − lr × ∂L/∂widentical to Session 3's gradient descent — only the gradient is harder to get

Why it is called back-propagation

The error is known at the output. To find a first-layer weight's share of the blame you have to pass responsibility backwards through every layer in between, multiplying derivatives as you go — the chain rule, applied layer by layer.

what Keras hides from you
# this one line is forward + backward + update
model.fit(X_train, y_train, epochs=20)

# under it, per batch:
#   1. forward  — compute predictions
#   2. loss     — compare with the truth
#   3. backward — gradient for every weight
#   4. update   — w -= lr * gradient
Why you should still know it

Because when training goes wrong — loss stuck, loss NaN, loss exploding — the fix is nearly always in that loop: learning rate too high, activations saturating, or gradients vanishing before they reach the early layers. Session 6 shows that last one happening in slow motion.

Hands-on · Module 1

One forward pass, by hand

20 minutes · pairs

One forward pass, by hand

Two inputs, one hidden layer of two neurons, one output. Calculators out, no code yet.

01Inputs x = [1.0, 0.5]. Hidden weights w1 = [0.3, 0.8], w2 = [-0.4, 0.6], biases both 0.1.
02Compute z for each hidden neuron, then apply ReLU.
03Output weights [0.7, -0.5], bias 0.2. Compute the output z.
04Apply sigmoid to get a probability.
05Now reproduce it in numpy and check the two agree to four decimal places.
your check
import numpy as np

x  = np.array([1.0, 0.5])
W1 = np.array([[0.3, 0.8],
               [-0.4, 0.6]])
b1 = np.array([0.1, 0.1])

z1 = W1 @ x + b1
a1 = np.maximum(0, z1)            # ReLU

W2 = np.array([0.7, -0.5])
z2 = W2 @ a1 + 0.2
out = 1 / (1 + np.exp(-z2))    # sigmoid

print(z1, a1, z2, out)
Do it once, believe it forever

Every deep network is this, scaled up and repeated. Students who do this by hand stop treating neural networks as magic — which also makes them much better at debugging one.

2.1 · Activations

Three activation functions, and where each belongs

The shape is the point: where the curve is flat, learning stops.

ReLUSigmoidtanh
LayerUseWhy
Hidden layersReLUFast, and gradients survive for positive inputs
Binary outputSigmoidGives one probability in (0,1)
Multi-class outputSoftmaxProbabilities across classes that sum to 1
Regression outputNoneYou want any real number, unsquashed
The mistake to avoid

Sigmoid in hidden layers. Its gradient is near zero for large positive or negative inputs, so corrections die on the way back — the vanishing gradient problem, which Session 6 makes visible. ReLU does not have that flat region on the positive side, which is why it took over.

If ReLU neurons go silent

A neuron stuck outputting 0 for every input is "dead" — its gradient is zero so it never recovers. LeakyReLU leaks a small negative slope and fixes it.

2.2 · CNNs

A convolution slides a filter and builds a feature map

7×7 input, 3×3 filter, stride 1 → a 5×5 feature map, one cell per filter position.

3×3 filter windowfeature map computed so far
Definition

Convolution

Sliding a small grid of weights across an image, computing one number per position. The same filter is reused everywhere, so an edge is detected the same way wherever it appears.

Why not just use Dense layers on images?

A 200×200 colour image flattened is 120,000 inputs. One dense layer of 128 units would need 15 million weights — and it would have to learn what an edge looks like separately in every position. A conv filter is 9 weights, reused across the whole image.

Layers are blocks you stack

Add or remove one and the shapes recompute. Conv deepens; Pool halves width and height.

2.3 · Keras

A working network is about fifteen lines

build, compile, train
import tensorflow as tf
from tensorflow.keras import layers, models

model = models.Sequential([
    layers.Flatten(input_shape=(28, 28)),
    layers.Dense(128, activation="relu"),
    layers.Dropout(0.3),
    layers.Dense(64,  activation="relu"),
    layers.Dense(10,  activation="softmax"),
])

model.compile(
    optimizer="adam",
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)

history = model.fit(
    X_train, y_train,
    validation_split=0.2,   # ← watch this, not train loss
    epochs=30, batch_size=64,
)
ChoiceUse
Binary targetsigmoid + binary_crossentropy
Multi-class, integer labelssoftmax + sparse_categorical_crossentropy
Multi-class, one-hot labelssoftmax + categorical_crossentropy
Regressionno activation + mse

The mismatch that wastes an hour

Using categorical_crossentropy with integer labels. It trains, produces nonsense accuracy, and the error message does not say why. Match the loss to your label format.

Always set validation_split

Without it you are watching training loss, which falls forever whether or not the model is learning anything useful. Validation loss is the only curve that tells you the truth.

from tensorflow.keras.datasets import fashion_mnist

(X_tr, y_tr), (X_te, y_te) = fashion_mnist.load_data()

# pixels 0-255 -> 0-1. Networks need scaled inputs.
X_tr = X_tr / 255.0
X_te = X_te / 255.0

print(X_tr.shape)   # (60000, 28, 28)
print(model.count_params())

Why scaling matters here too

Same reason as Session 1. Unscaled inputs of 0–255 produce enormous first-layer activations, the gradients explode, and the loss becomes NaN in about three batches.

3.1 · Dropout

Move the dropout — watch the curves change shape

Set dropout to 0 and watch validation loss turn upward early. Push it to 0.7 and both curves stall.

training lossvalidation lossbest epoch
Definition

Dropout

Randomly switching off a fraction of neurons on each training batch, so the network cannot lean on any single one and has to spread what it learns.

Verdict

—

Read the gap, not the level

The distance between the two curves is the overfitting. A model with training loss 0.05 and validation 0.40 has memorised; one with 0.22 and 0.25 has generalised, even though its training loss looks worse.

Dropout only runs during training

At prediction time every neuron is active. Keras handles the switch for you — but it is why evaluation accuracy is often slightly better than the training accuracy you saw.

3.2 · Reading curves

Four shapes, four diagnoses

What you seeDiagnosisDo
Both falling, small gapHealthyKeep training
Train falls, validation risesOverfittingStop earlier, add dropout, get more data
Both plateau highUnderfittingBigger network, train longer, better features
Loss spikes or goes NaNLearning rate too highDrop it 10×; check input scaling
The only epoch count that is right

Whatever epoch validation loss bottomed out at. Everything after it is the model memorising — and you can see it happening while the training curve keeps looking better.

plot both, always
import matplotlib.pyplot as plt

h = history.history

plt.figure(figsize=(7, 4))
plt.plot(h["loss"],     label="train")
plt.plot(h["val_loss"], label="validation")
plt.axvline(np.argmin(h["val_loss"]),
            color="red", linestyle="--",
            label="best epoch")
plt.xlabel("epoch"); plt.ylabel("loss")
plt.legend(); plt.tight_layout(); plt.show()

print(f"best epoch: {np.argmin(h['val_loss'])}")

Plot it before you report anything

A final accuracy number with no curve behind it tells you nothing about whether the model was still improving or had been memorising for fifteen epochs.

3.3 · Early stopping

Let Keras stop at the right epoch for you

Definition

Early stopping

A callback that watches validation loss and halts training when it stops improving — optionally restoring the weights from the best epoch.

restore_best_weights is the line people forget

Without it, training stops at the right time but leaves you holding the weights from five epochs after the best one — which is exactly the overfitted version you were trying to avoid.

the two callbacks worth always using
from tensorflow.keras.callbacks import (
    EarlyStopping, ReduceLROnPlateau)

stop = EarlyStopping(
    monitor="val_loss",
    patience=5,                 # wait 5 epochs before giving up
    restore_best_weights=True,  # ← the important one
)

reduce = ReduceLROnPlateau(
    monitor="val_loss",
    factor=0.5,                 # halve the learning rate
    patience=3,
)

history = model.fit(
    X_tr, y_tr,
    validation_split=0.2,
    epochs=200,                 # set it high; the callback decides
    callbacks=[stop, reduce],
)
restore_best_weights is the line people forget

Without it, training stops at the right time but leaves you holding the weights from five epochs after the best one — which is exactly the overfitted version you were trying to avoid.

Set epochs high on purpose

With early stopping in place, epochs=200 does not mean 200 epochs. It means "train until it stops helping". That is almost always what you actually wanted.
