What is a function?

whatIn plain words

A function is a named block of code that does one job. You write it once with def, then call it as many times as you like. It can take inputs (parameters) and give back an output with return.

likeEveryday analogy

A drinks machine at the kopitiam: put in your choice and money (input), it makes the drink (work), and out comes your teh tarik (output). You don't rebuild the machine for every cup.

rulesTheory: the key rules

  • def name(params): then an indented body
  • return sends a value back and ends the function
  • No return gives back None
  • print ≠ return: print shows, return gives

Parameters: how a function gets its inputs

whatIn plain words

Parameters are the names in the def line. Arguments are the real values you pass when you call it. Python matches them by position, by keyword, or collects any extras with *args and **kwargs.

likeEveryday analogy

Ordering at a mamak: "roti canai" is the main order (positional), "kuah campur" is a named choice (keyword), and "plus 2 teh, 1 milo…" is any number of extras (*args).

rulesTheory: the key rules

  • Positional arguments fill parameters in order
  • Defaults (discount=0.0) make a parameter optional
  • Keyword arguments (discount=0.1) can go in any order
  • *args collects a tuple, **kwargs collects a dict
syntax at a glance
def f(a, b=0, *args, key=None, **kwargs):
    ...

f(1)                 # a=1, b=0
f(1, 2, 3, 4)        # args=(3, 4)
f(1, key="x", z=9)   # kwargs={"z": 9}

Common mistakes

  • A default like items=[] is shared between calls. Use None instead.
  • Putting a positional argument after a keyword one is a SyntaxError.

One receipt function, many ways to call it

receipt.py
def make_receipt(customer, *items, discount=0.0, **notes):
    """Print a receipt. Each item is a (name, price) pair."""
    subtotal = sum(price for _, price in items)
    total = subtotal * (1 - discount)
    print(f"Customer: {customer}")
    for name, price in items:
        print(f"  {name:<12} RM{price:>6.2f}")
    if discount:
        print(f"  {'Discount':<12} {discount:>8.0%}")
    print(f"  {'TOTAL':<12} RM{total:>6.2f}")
    for key, value in notes.items():
        print(f"  note - {key}: {value}")
    print()


# positional argument + any number of items (*items)
make_receipt("Aisyah", ("Teh Tarik", 3.00), ("Roti Canai", 2.50))

# keyword argument (discount=) + extra keyword notes (**notes)
make_receipt("Darren", ("Nasi Lemak", 6.50), ("Kopi O", 2.50),
             discount=0.10, table=4, sugar="less")

Scope, type hints and docstrings

whatIn plain words

Scope decides where a name can be seen: names made inside a function stay inside. Type hints (price: float) and docstrings ("""…""") don't change what the code does. They tell people and tools what it expects.

likeEveryday analogy

Scope is like rooms in a house. What's in your bedroom (local) isn't visible from the living room, but the family TV (global) is shared. Type hints are the labels on the fuse box.

rulesTheory: the key rules

  • Python looks names up in L → E → G → B order
  • Variables made inside a function are local
  • Hints: param: type and -> return type
  • A docstring is the first string in the function

checkout.py
TAX_RATE = 0.06                      # Global: visible everywhere in this file


def checkout(prices: list[float], member: bool = False) -> float:
    """Return the total to pay.

    prices: item prices in RM
    member: members get 5% off before tax
    """
    total = sum(prices)              # Local: only exists inside checkout()

    def discount(amount: float) -> float:
        rate = 0.05                  # Local to discount()
        return amount * (1 - rate) if member else amount   # 'member' = Enclosing

    return round(discount(total) * (1 + TAX_RATE), 2)       # 'round' = Built-in


print(checkout([10.0, 5.5]))                 # 16.43
print(checkout([10.0, 5.5], member=True))    # 15.61
print(checkout.__doc__.splitlines()[0])      # first docstring line
# print(total)  -> NameError: 'total' only lives inside the function

Build: ride-hailing fare calculator

real lifeKopitiam bill: service charge, SST, cash rounding, split

Five friends finish lunch. The bill needs a 10% service charge, then 6% SST, then rounding to the nearest 5 sen for cash, then a split. Each step is one small typed function.

kopitiam_bill.py
"""Kopitiam bill calculator: service charge, SST, cash rounding, split."""

SERVICE_RATE = 0.10
SST_RATE = 0.06


def subtotal(prices: list[float]) -> float:
    """Add up all item prices."""
    return sum(prices)


def add_charges(amount: float, service: bool = True) -> float:
    """Add an optional 10% service charge, then 6% SST."""
    if service:
        amount *= 1 + SERVICE_RATE
    return amount * (1 + SST_RATE)


def round_to_5_sen(amount: float) -> float:
    """Round to the nearest 5 sen, like a cash payment in Malaysia."""
    return round(round(amount / 0.05) * 0.05, 2)


def split_bill(total: float, people: int) -> float:
    """Return each person's share of the bill."""
    if people < 1:
        raise ValueError("need at least 1 person")
    return round(total / people, 2)


order = [6.50, 6.50, 3.00, 3.00, 2.80]   # 2 nasi lemak, 2 teh tarik, 1 kopi
before = subtotal(order)
total = round_to_5_sen(add_charges(before))

print(f"Subtotal        : RM{before:.2f}")
print(f"+ service + SST : RM{add_charges(before):.4f}")
print(f"Cash total      : RM{total:.2f}")
print(f"Each of 3 pays  : RM{split_bill(total, 3):.2f}")
print(f"Takeaway (no service): RM{round_to_5_sen(add_charges(before, service=False)):.2f}")

Comprehensions: a loop in one readable line

whatIn plain words

A comprehension builds a new list, dict or set from an existing one, with an optional filter, in one line. It replaces the pattern "make empty list → loop → if → append".

likeEveryday analogy

Sorting durians at a stall: from all the durians (source), keep the ripe ones (filter), weigh each one (transform), and put them in a new basket (result).

rulesTheory: the key rules

  • [expr for x in items if cond] gives a list
  • {k: v for …} gives a dict, {expr for …} a set
  • Read it as: give me expr for each x where cond
  • Too long to read in one go? Use a normal loop.

Loop vs comprehension: same result, less code

prices = [4.50, 12.00, 8.90, 25.00, 3.20]

# Loop version: 4 lines
with_sst = []
for p in prices:
    if p > 5:
        with_sst.append(round(p * 1.06, 2))

# Comprehension version: 1 line, same result
with_sst2 = [round(p * 1.06, 2) for p in prices if p > 5]
print(with_sst == with_sst2, with_sst2)

# dict comprehension: name -> length
names = ["Aisyah", "Darren", "Nurin"]
print({n: len(n) for n in names})

# set comprehension: unique, cleaned codes
codes = ["JB01", "kl02", "jb01", "PG03", "KL02"]
print(sorted({c.upper() for c in codes}))

lambda: a tiny function you don't bother naming

whatIn plain words

lambda x: x[1] is a one-line function with no name. It is used mostly as the key= for sorted(), min() and max(), telling them what to compare.

likeEveryday analogy

Telling a teacher "line up by height" or "line up by birthday". The students are the same; only the rule you hand over (the key) changes.

rulesTheory: the key rules

  • lambda params: expression, one expression, no return
  • key= is called on every item to get the sort value
  • reverse=True gives highest first
  • Return a tuple to sort by several things
syntax at a glance
sorted(items, key=lambda s: s[1], reverse=True)
max(items, key=lambda s: s[1])

# same as:
def by_mark(s):
    return s[1]

Common mistakes

  • sorted() returns a new list. list.sort() changes the list and returns None.
  • Long lambdas are hard to read. Write a def instead.

students = [("Aisyah", 88), ("Darren", 92), ("Nurin", 75), ("Tan", 92)]

collections: ready-made tools you'd otherwise write

whatIn plain words

The collections module gives you smarter containers: Counter counts things, defaultdict groups things without KeyError, and deque keeps a fast queue or the "last N" items.

likeEveryday analogy

Counter is the tally sheet at a voting booth. defaultdict is a filing cabinet that makes a new folder the moment you need one. deque is the queue at the bank counter.

rulesTheory: the key rules

  • Counter(items).most_common(n) gives the top n
  • defaultdict(list): missing key → empty list
  • deque(maxlen=3) drops the oldest item automatically
  • All three are in the standard library: nothing to install

# Counter: count anything

by_class = defaultdict(list)

    recent.append(page)
print(list(recent))

Build: word-frequency analyser

real lifeWhatsApp lunch order: tally for the stall, bill per person

Every lunch the office group chat fills with orders. This script reads the messages, cleans the spelling, counts what to order, and works out who pays what.

lunch_orders.py
"""Tally a WhatsApp group lunch order and work out who pays what."""
from collections import Counter

chat = """\
Aisyah: nasi lemak, teh tarik
Darren: mee goreng, kopi o
Nurin: nasi lemak, milo ais
Tan: Nasi Lemak , teh tarik
Sasha: roti canai, kopi o"""

PRICES = {"nasi lemak": 6.50, "mee goreng": 7.00, "roti canai": 2.50,
          "teh tarik": 3.00, "kopi o": 2.50, "milo ais": 3.50}

# 1. parse each line -> {name: [items]}  (dict + list comprehension)
orders = {
    name.strip(): [item.strip().lower() for item in items.split(",")]
    for name, items in (line.split(":", 1) for line in chat.splitlines())
}

# 2. count every item for the stall
counts = Counter(item for items in orders.values() for item in items)
print("Order for the stall:")
for item, qty in counts.most_common():
    print(f"  {qty} x {item.title()}")

# 3. each person's bill, highest first
bills = {name: sum(PRICES[i] for i in items) for name, items in orders.items()}
print("\nWho pays what:")
for name, amount in sorted(bills.items(), key=lambda kv: kv[1], reverse=True):
    print(f"  {name:<7} RM{amount:>5.2f}")
print(f"  {'TOTAL':<7} RM{sum(bills.values()):>5.2f}")

Find the top 10 words in a news article

word_freq.py — starter
from collections import Counter
from pathlib import Path

STOP = {"the", "a", "and", "to", "of", "in"}

text = Path("article.txt").read_text().lower()
words = [w.strip(".,!?\"'()") for w in text.split()]
words = [w for w in words if w and w not in STOP]

for word, n in Counter(words).most_common(10):
    print(f"{word:<15}{n}")

Virtual environments: one project, one sealed box

whatIn plain words

A virtual environment (venv) is a private folder of Python packages for one project, so projects can't break each other. requirements.txt lists the exact packages so anyone can rebuild the same box.

likeEveryday analogy

A lunch box per child. Each has its own food (packages), and one child's sambal doesn't spill into another's rice.

rulesTheory: the key rules

  • Create once per project: python -m venv .venv
  • Activate it before installing or running
  • pip freeze > requirements.txt records versions
  • Never commit .venv/; commit requirements.txt

Git: save points for your code

whatIn plain words

Git records snapshots (commits) of your project so you can go back in time. GitHub keeps a copy online, so a dead laptop never kills your work, and others can see it.

likeEveryday analogy

Save points in a game. You save before the boss fight; if it goes wrong, you reload. Pushing to GitHub is uploading your save to the cloud.

rulesTheory: the key rules

  • git add chooses changes, git commit saves them
  • git push uploads, git pull downloads
  • Commit messages say why: "fix grade() at 80"
  • .gitignore keeps .venv, .env and caches out

PEP 8 and ruff: code that looks professional

whatIn plain words

PEP 8 is Python's official style guide: naming, spacing, line length. ruff is a tool that checks your code against it in milliseconds and fixes most problems for you.

likeEveryday analogy

Grammar and spell-check for code. People can still read messy writing, but tidy writing is faster to read and looks trustworthy.

rulesTheory: the key rules

  • snake_case for variables and functions
  • PascalCase for classes, UPPER_CASE for constants
  • 4 spaces per indent; imports at the top
  • ruff check --fix then ruff format
syntax at a glance
TAX_RATE = 0.06            # constant


class BankAccount:         # class
    def deposit(self, amount):   # method
        total_paid = amount      # variable

Common mistakes

  • Naming a variable l, O or I: they look like 1 and 0.
  • Unused imports left behind after refactoring.

real lifeHouse bills splitter: a clean, typed, ruff-passing script

Four housemates pay different bills each month. This script works out each person's balance and the fewest transfers to settle up. It is typed, has docstrings, and passes ruff check: the standard for every script from now on.

house_bills.py
"""Split shared house bills and tell everyone who pays whom."""

Expense = tuple[str, str, float]   # (who paid, what for, amount)

EXPENSES: list[Expense] = [
    ("Aisyah", "Electricity", 180.00),
    ("Darren", "Water", 36.00),
    ("Nurin", "Internet", 129.00),
    ("Aisyah", "Groceries", 95.50),
    ("Tan", "Gas cylinder", 26.60),
]


def total_paid(records: list[Expense]) -> dict[str, float]:
    """Return how much each person has paid so far."""
    paid: dict[str, float] = {}
    for person, _, amount in records:
        paid[person] = paid.get(person, 0.0) + amount
    return paid


def balances(paid: dict[str, float]) -> dict[str, float]:
    """Positive = should get money back, negative = owes money."""
    share = sum(paid.values()) / len(paid)
    return {person: round(amount - share, 2) for person, amount in paid.items()}


def settle(balance: dict[str, float]) -> list[str]:
    """Return the fewest simple 'X pays Y' transfers to even things out."""
    owe = [[p, -a] for p, a in balance.items() if a < 0]
    get = [[p, a] for p, a in balance.items() if a > 0]
    steps = []
    while owe and get:
        amount = round(min(owe[0][1], get[0][1]), 2)
        steps.append(f"{owe[0][0]} pays {get[0][0]} RM{amount:.2f}")
        owe[0][1] -= amount
        get[0][1] -= amount
        if owe[0][1] < 0.01:
            owe.pop(0)
        if get[0][1] < 0.01:
            get.pop(0)
    return steps


paid = total_paid(EXPENSES)
print(f"Total this month: RM{sum(paid.values()):.2f}, "
      f"RM{sum(paid.values()) / len(paid):.2f} each")
for person, amount in balances(paid).items():
    print(f"  {person:<7} {amount:+8.2f}")
print("To settle up:")
for step in settle(balances(paid)):
    print("  " + step)
