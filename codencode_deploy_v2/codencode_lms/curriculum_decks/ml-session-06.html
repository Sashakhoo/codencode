What does a neuron compute?

A weighted sum plus a bias, passed through an activation. Everything else is repetition.

Which activation where?

ReLU in hidden layers; sigmoid or softmax on the output; nothing on a regression output.

Which curve tells the truth?

Validation loss. Training loss falls forever whether or not the model is learning anything useful.

Today adds one idea to that: the network keeps a note to itself between steps, so the order of the data starts to matter.

The one rule that governs this whole session

Never let the model see the future. Every mistake in time-series ML — random splits, centred rolling windows, scaling before the split — is a version of that single error, and every one of them produces a beautiful validation score that collapses in production.

1.1 · Definitions

Time series: when the order is part of the data

Definition

Time series

Observations recorded in time order, where the order carries information. Shuffling the rows destroys something real — which is not true of ordinary tabular data.

The test

Shuffle your rows. If nothing is lost, it is not a time series — it is a table that happens to have a date column. If shuffling destroys the pattern you care about, order is a feature and you must respect it.

ComponentWhat it is
TrendThe long slow direction — sales growing year on year
SeasonalityA repeating cycle — weekends, Ramadan, December
CyclicLonger waves with no fixed period — economic cycles
NoiseWhat is left. Do not try to model it.
the first thing to do with any series
import pandas as pd

df = pd.read_csv("sales.csv", parse_dates=["date"])
df = df.sort_values("date").set_index("date")

# is anything missing in the middle?
full = pd.date_range(df.index.min(), df.index.max(), freq="D")
print(f"gaps: {len(full) - len(df)} days")

# fill them — a model cannot infer a missing Tuesday
df = df.reindex(full).ffill()

Sort first, always

Every rolling window, lag and split below assumes the rows are in time order. One unsorted read and every feature you build is quietly wrong.

1.2 · What breaks

Why the Session 2 workflow does not survive contact with time

1 · Random splits leak the future

train_test_split(shuffle=True) puts December in training and August in test. The model has seen the future and your score is fiction.

2 · Rows are not independent

Standard cross-validation assumes every row is an independent draw. Today's sales are obviously related to yesterday's — so k-fold quietly breaks its own assumption.

3 · The pattern moves

A model fitted on 2023 shopping behaviour may simply be wrong about 2026. Time series drift in a way that customer-height data does not.

the split that is actually valid
# WRONG — shuffles time
X_tr, X_te = train_test_split(X, shuffle=True)

# RIGHT — cut by date
cut = "2025-07-01"
train = df.loc[:cut]
test  = df.loc[cut:]

# and for cross-validation:
from sklearn.model_selection import TimeSeriesSplit

tscv = TimeSeriesSplit(n_splits=5)
for tr_idx, te_idx in tscv.split(X):
    # each fold trains on the past, tests on what came next
    pass
TimeSeriesSplit in one sentence

Fold 1 trains on months 1–2 and tests on month 3; fold 2 trains on 1–3 and tests on 4, and so on. The training window only ever grows forward, which is the only honest way to validate a forecast.

1.3 · RNNs

An RNN reads one step at a time and passes itself a note

Watch the input pulses rise into each cell and the amber hidden state travel to the next step.

input arriving at each stephidden state — what it remembers
Definition

Recurrent neural network

A network that processes a sequence one step at a time, carrying a hidden state forward from each step to the next. The same weights are reused at every step.

One cell, not five

Drawn unrolled it looks like five boxes; it is one box used five times. That is why an RNN handles sequences of any length with a fixed number of parameters.

The hidden state is a bottleneck

Everything the network knows about everything it has read is squeezed into that one vector. That is the source of both its power and, as the next module shows, its main failure.

Why it suits time series

Monday's reading affects Tuesday's. The architecture takes order seriously instead of treating each row as an unrelated sample.

2.1 · Vanishing gradient

The lesson fades on the way back

Bars show how much gradient survives to each step: 1.00 → 0.50 → 0.25 → 0.13 → 0.06.

error travelling back — shrinking every step
What is happening

Training sends the error backwards through every time step, and each step multiplies it by a number less than one. After five steps it is ~0.06 of its original size. After twenty, effectively zero.

What that means in practice

"The cat, which had been missing since the storm last week, was finally found."

To pick was over were the model must still remember cat — eleven words back. A plain RNN has lost it.

The same thing in forecasting

A plain RNN asked to use 60 days of history effectively uses about the last 10. The early part of the window contributes almost nothing to the weights.

Why not just make it bigger?

More neurons do not help — the problem is the depth in time, not the width. The fix has to change how information travels between steps, which is exactly what the LSTM does.

2.3 · Memory retention

How far back can it still remember?

Same information, tracked backwards through 24 steps.

plain RNN — decays fastLSTM — holds while the forget gate stays open
Why the LSTM line is nearly flat

On the cell state the memory is multiplied by the forget gate and added to — there is no repeated squashing through an activation. If the network learns to keep the forget gate near 1, information travels almost untouched across many steps.

Sequence lengthUse
Under ~10 stepsPlain RNN is fine — or even a tree model on lag features

GRU, in one line

A simplified LSTM with two gates instead of three. Trains faster, performs about the same on most problems. Try both — it is a one-word change in Keras.

The answer to question 3

Mid-sentence, or mid-week. The cell is accumulating context it is not ready to act on yet. Keeping memory and emitting output are separate decisions — which is precisely why there are three gates and not one.

What to listen for in question 5

A good answer is concrete: "it decides what fraction of what it already knew to keep — 1 means keep everything, 0 means wipe the slate." If a student says "it forgets things", push for the fraction.

3.1 · Shaping data

The reshape that trips everyone up

What Keras expects

An LSTM wants a 3-D array: (samples, timesteps, features). A flat series of 1,000 daily values with a 30-day window becomes 970 samples × 30 timesteps × 1 feature. Getting this wrong is the single most common error in a first LSTM.

(samples, timesteps, features)970 × 30 × 1 — for 1,000 days, a 30-day window, one variable
the windowing function you will reuse forever
import numpy as np

def make_sequences(series, window):
    """Flat series -> (samples, window, 1) and the next value."""
    X, y = [], []
    for i in range(len(series) - window):
        X.append(series[i : i + window])
        y.append(series[i + window])
    X = np.array(X).reshape(-1, window, 1)
    return X, np.array(y)

X, y = make_sequences(values, window=30)
print(X.shape, y.shape)   # (970, 30, 1) (970,)

Split AFTER windowing, and by position

X[:800] for training, X[800:] for test. Never shuffle. The last training sample must end before the first test sample begins.

Scaling, done in the right order

Fit the scaler on the training period only, then transform both. Fitting on the whole series lets the future's minimum and maximum leak into your training data — the Session 1 leakage rule, in time-series form.

3.2 · Building it

The model is the short part

a complete LSTM forecaster
from tensorflow.keras import layers, models, callbacks

model = models.Sequential([
    layers.LSTM(64, input_shape=(30, 1),
                return_sequences=True),
    layers.Dropout(0.2),
    layers.LSTM(32),          # last one: no return_sequences
    layers.Dense(16, activation="relu"),
    layers.Dense(1),           # one number out
])

model.compile(optimizer="adam", loss="mse", metrics=["mae"])

stop = callbacks.EarlyStopping(
    monitor="val_loss", patience=8,
    restore_best_weights=True)

hist = model.fit(
    X_tr, y_tr,
    validation_split=0.15,
    shuffle=False,          # ← keep time order!
    epochs=200, batch_size=32,
    callbacks=[stop],
)
Definition

return_sequences

True when another recurrent layer follows — it needs an output at every timestep. False (the default) on the last one, which returns only the final step's output.

shuffle=False is not optional

Keras shuffles by default. On sequences that scrambles which window is used for validation, so your validation set ends up containing windows from before your training data.

Start smaller than you think

64 then 32 units is already generous for a single daily series. Time-series datasets are usually small, and a large LSTM will memorise three years of sales in about twelve epochs.

3.3 · Evaluating

The only forecast plot worth showing

Everything right of the red line is data the model never saw — and it is later in time, not randomly sampled.

actualpredictedforecast starts
Why plot it at all

An MAE of 0.04 tells you nothing about where the model fails. The plot shows you immediately whether it tracks turning points or just lags one step behind the actual line.

The lag trap

If your forecast looks like the actual series shifted one step right, the model has learned "tomorrow ≈ today". It will score well on MAE and is worth nothing. Always compare against that naive baseline explicitly.

the baseline that keeps you honest
