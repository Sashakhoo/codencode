Why does order matter in if/elif?

Python takes the first branch that is True and skips the rest — so a narrower test placed after a wider one never runs.

Where do conditional bugs live?

At the boundaries. Exactly 80, exactly RM 5,000. A > that should be >=.

What is a guard clause?

A check at the top that handles the bad case and returns straight away, so the real work sits unindented below.

1.1 · Why loops

The same three lines, four hundred times

Definition

Loop

A block of code that Python runs more than once. You write the body once; the loop decides how many times it runs and what it is working on each time.

what you are doing now
print("Aisyah")
print("Wei Ming")
print("Kumar")
# ... and 397 more lines
# add one student -> edit the file
what you will do from today
students = ["Aisyah", "Wei Ming", "Kumar"]

for name in students:
    print(name)

# 3 students or 3,000 — same four lines
The real argument for loops is not typing

It is that the logic lives in one place. Four hundred copied lines means four hundred places a bug can hide and four hundred edits when the rule changes. One loop body means one.

Two kinds, one question

Ask yourself: do I know how many times? If yes — or if you have a collection to walk through — use for. If you are waiting for a condition to change, use while.

1.2b · range()

range() and the off-by-one that catches everyone

range gives you numbers, not a list you can see
for i in range(5):
    print(i)        # 0 1 2 3 4  — five numbers, stops BEFORE 5

for i in range(1, 6):
    print(i)        # 1 2 3 4 5  — start, stop

for i in range(0, 21, 5):
    print(i)        # 0 5 10 15 20 — start, stop, step

for i in range(5, 0, -1):
    print(i)        # 5 4 3 2 1 — counting down
Definition

Half-open range

range(a, b) includes a and excludes b. It feels arbitrary until you notice range(len(x)) then gives exactly the valid indices, and range(0,5) + range(5,10) tile perfectly with no overlap.

when you need the index as well as the value
# clumsy
for i in range(len(students)):
    print(i, students[i])

# the Python way
for i, name in enumerate(students):
    print(f"{i+1}. {name}")

The rule

If you only need the values, loop over the collection directly. Reach for range() when you genuinely need numbers.

1.3 · while

while — running until something changes

for versus while
# for: I know the collection
for item in cart:
    total += item.price

# while: I am waiting for a condition
attempts = 0
while attempts < 3:
    pin = input("PIN? ")
    if pin == correct:
        print("Welcome")
        break
    attempts += 1
else:
    print("Card locked")
That is your ATM from last week — properly

Session 2 you wrote the three attempts out by hand. The while version works for three attempts or thirty, and the else on a loop runs only when it finished without a break — exactly the "ran out of attempts" case.

break and continue
for n in numbers:
    if n < 0:
        continue      # skip this one, go round again
    if n > 100:
        break         # stop the loop entirely
    print(n)

The infinite loop

while True: with no break, or a counter you forgot to increase, and your terminal hangs. Ctrl+C stops it. Before you run any while loop, point at the line that will eventually make the condition False.

2.1 · Lists

Press the buttons — watch the indices move

Negative indices count from the end — cart[-1] is always the last item.

addedabout to be removed
Definition

List

An ordered, changeable collection. Position is meaningful, duplicates are allowed, and the first item is at index 0.

Watch insert(0) carefully

Everything after it shifts one index right — which is why appending is cheap and inserting is not.

the operations on screen
cart = ["roti", "telur", "susu"]

cart.append("kopi")    # on the end
cart.insert(0, "ais")   # at the front
cart.pop()                # remove + return the last

print(cart[0], cart[-1])   # first, last
print(cart[1:3])          # a slice — 1 and 2, not 3
2.2 · Dictionaries

When position is meaningless and names are not

Definition

Dictionary

A collection of key: value pairs. You look things up by key instead of by position — contact["phone"], not contact[1].

list versus dict — the same data, two ways
# as a list — what is at index 2 again?
p = ["Aisyah", 17, "JB", "0127..."]
print(p[2])            # you have to remember

# as a dict — it says what it is
p = {
    "name":  "Aisyah",
    "age":   17,
    "city":  "JB",
    "phone": "0127...",
}
print(p["city"])
the four things you will do constantly
# 1 — read, safely
print(p.get("email", "not given"))
#    p["email"] would raise KeyError

# 2 — add or update (same syntax)
p["email"] = "a@codencode.my"

# 3 — check before you look
if "phone" in p:
    print(p["phone"])

# 4 — loop over both at once
for key, value in p.items():
    print(f"{key:>6}: {value}")
Pick by the question you will ask

"Give me the third one" or "in what order?" → list. "Give me Aisyah's phone number" → dictionary. A contact book is a list of dictionaries, which is exactly what the demo builds next.

2.3 · Nested loops

A loop inside a loop — like a Russian doll

Open the outer doll to find the inner one; open that to reach the core. The core is the loop body — it runs the most.

outer loop · iinner loop · jthe body · print()
3 x 3 = 9 runs of the body
for i in range(1, 4):
    for j in range(1, 4):
        print(i, "x", j, "=", i*j)

The number that matters

The inner loop runs completely for every single turn of the outer one. 3 and 3 is 9. 1,000 and 1,000 is a million — and that is how a loop that looks innocent freezes a laptop.

3.1 · Loop patterns

Four shapes that cover almost everything

1 · Accumulate

Start at zero or empty, add to it each pass. Totals, counts, joining strings. total += x

2 · Filter

Walk the collection, keep only what passes a test. if ok: keep.append(x)

3 · Transform

Produce a new item from each old one. Prices to prices-with-tax, names to uppercase names.

4 · Search

Walk until you find it, then break. Remember the "found nothing" case.

all four, and the short form of the first three
# accumulate
total = 0
for p in prices: total += p

# filter
cheap = []
for p in prices:
    if p < 10: cheap.append(p)

# transform
with_tax = []
for p in prices: with_tax.append(p * 1.06)

# the comprehension — same thing, one line
cheap    = [p for p in prices if p < 10]
with_tax = [p * 1.06 for p in prices]
total    = sum(prices)
Write the long form first

Comprehensions are lovely once the loop is clear in your head. Write the four-line version, get it right, then collapse it. Nobody is impressed by a one-liner that returns the wrong answer.

3.2 · Saving

Making the contact book survive being closed

The problem with everything so far

Close the program and the data is gone. To keep it, write it to a file.

save and load with JSON
import json
# save — dump the whole list of dicts
with open("contacts.json", "w") as f:
    json.dump(book, f, indent=2)
# load — cope with the first ever run
try:
    with open("contacts.json") as f:
        book = json.load(f)
except FileNotFoundError:
    book = []   # no file yet

JSON

Text that looks almost exactly like Python lists and dicts — and it is what APIs speak.

the menu loop that makes it a real program
while True:
    choice = input("[1] list [2] add [3] find [q] quit: ")
    if choice == "q":
        save(book); break
    elif choice == "1": show(book)
    elif choice == "2": book.append(ask_contact())
    elif choice == "3": search(book)
3.3 · Debugging

Four loop bugs, and how to spot each

1 · The loop never ends

A while whose condition never becomes False — usually a counter you forgot to increase. Symptom: the cursor just sits there. Ctrl+C, then look for the line that should change the condition.

2 · Off by one

range(1, 10) when you meant range(1, 11). Symptom: the last item is missing. Print len() of what you produced and compare.

3 · Changing a list while looping over it

Removing items mid-loop makes Python skip the next one. Symptom: some items survive that should not. Build a new list instead.

4 · Accumulator reset inside the loop

total = 0 written one indent too far in. Symptom: the total equals the last item. Check the indentation.

bugs 3 and 4, seen properly
# BUG 3 — never do this
for x in nums:
    if x < 0:
        nums.remove(x)    # skips the next item

# fix — build a new list
nums = [x for x in nums if x >= 0]

# BUG 4 — spot the indent
for p in prices:
    total = 0          # resets every pass
    total += p

# fix — outside the loop
total = 0
for p in prices:
    total += p
The one debugging move for loops

print(i, item, total) as the first line of the body. You instantly see how many passes happened, in what order, and where the number went wrong. Delete it afterwards.

the word counter — the whole idea in six lines
text = input("Sentence: ").lower()
counts = {}

for word in text.split():
    word = word.strip(".,!?")
    counts[word] = counts.get(word, 0) + 1

for word, n in sorted(counts.items(),
                       key=lambda kv: kv[1], reverse=True):
    print(f"{word:<12} {n}")

counts.get(word, 0) + 1 is the trick

First time a word appears there is no key yet, so plain counts[word] would raise KeyError. .get(word, 0) says "or zero if it is new" — one line instead of an if.
