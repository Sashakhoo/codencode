Supervised or unsupervised?

Does a column hold the answer? If yes, supervised. Regression when that answer is a number.

Why three splits?

Train to learn, validation to tune, test opened once at the end. A reused test set stops being a test set.

Over or under?

Great on train and poor on test means overfitting. Poor on both means underfitting.

1.1 · Definitions

Regression predicts a number on a continuous scale

Definition

Regression

A supervised task where the target is a continuous number — one that can meaningfully take any value in a range, and where being close counts as being partly right.

The test that separates it from classification

Ask: is being nearly right worth anything? Predicting RM 495,000 for a RM 500,000 house is almost perfect. Predicting "cat" when the answer is "dog" is just wrong — there is no nearly. Continuous target, partial credit: regression.

Careful with numbers that aren't really numbers

Postcode 81100 is stored as a number but is a category — 81100 is not 'less than' 81200 in any useful sense. Star ratings 1–5 are ordinal: ordered, but the gap from 1 to 2 isn't the same as 4 to 5.

QuestionTargetTask
What will this house sell for?RM 480,000Regression
How many units next month?1,240Regression
How many days until failure?37.5Regression
Will this customer churn?yes / noClassification
Which defect type is this?one of 12Classification
A useful trick

A regression output can be turned into a decision with a threshold — predict the number, then act when it crosses a line. Often more useful than classifying directly, because you keep the magnitude.

1.2 · The family

Five regressors, and what each is for

ModelFitsReach for it when
LinearA straight line / flat planeYou need to explain the result to a client
PolynomialA curveThe relationship bends, and you know it does
Ridge / LassoA penalised straight lineMany features, or features that move together
Random ForestMany step functions averagedNon-linear tabular data, minimal tuning
XGBoostTrees correcting treesYou want the strongest tabular score
The trade you are making

Left to right you gain accuracy and lose explainability. A linear model hands you a coefficient per feature. XGBoost hands you a number and a shrug — you can get importances, but not "every extra square foot adds RM 310".

all five share one interface
from sklearn.linear_model import LinearRegression, Ridge, Lasso
from sklearn.ensemble import RandomForestRegressor
from xgboost import XGBRegressor

models = {
    "linear": LinearRegression(),
    "ridge" : Ridge(alpha=1.0),
    "lasso" : Lasso(alpha=0.1),
    "forest": RandomForestRegressor(random_state=42),
    "xgb"   : XGBRegressor(random_state=42),
}

for name, m in models.items():
    m.fit(X_tr, y_tr)
    print(f"{name:8s} {m.score(X_te, y_te):.3f}")

Always fit the linear one

Even when you expect to ship the boosted model. It is your interpretable reference point, and if it wins you have just saved yourself a lot of complexity.

1.3 · Linear regression

The line, the loss, and how it gets found

ŷ = w₀ + w₁x₁ + w₂x₂ + … + wₙxₙw₀ is the intercept · each wᵢ is how much ŷ moves per one-unit rise in xᵢ, holding the rest fixed
MSE = (1/n) Σ (yᵢ − ŷᵢ)²The loss. Squaring makes every error positive and punishes big misses much harder than small ones
What 'fitting' means

Finding the set of weights that makes that loss as small as possible. For plain linear regression there is a closed-form solution, so sklearn solves it directly. For almost everything else — and always for neural networks — you walk downhill instead, which is the figure on the next slide.

reading the coefficients
model = LinearRegression().fit(X_tr, y_tr)

for name, w in zip(X.columns, model.coef_):
    print(f"{name:16s} {w:>10.2f}")
print(f"intercept        {model.intercept_:>10.2f}")

# size_sqft            310.44
# bedrooms           8_120.10
# age_years         -2_940.77

Say it in words

"Holding everything else constant, each extra square foot is worth about RM 310, and each year of age costs about RM 2,940." That sentence is why linear regression survives.

Only if you scaled

Coefficients are only comparable to each other when the features share a scale. Unscaled, a big coefficient might just mean a small unit.

1.3 · Gradient descent

How a model walks downhill to the answer

Notice the steps get smaller near the bottom all by themselves — the gradient shrinks as the slope flattens. Nobody schedules that.

current positionslope at that pointpath so far
Definition

Gradient descent

Start anywhere. Measure the slope. Take a step downhill, sized by the learning rate. Repeat until the slope is flat — that's the minimum.

Verdict

—

Try 0.04, then 1.2, then 1.8. Too small and you never arrive; too big and you bounce across the valley; too big again and the loss explodes.

2.1 · Regularisation

Ridge and Lasso: two ways to rein a model in

Same five coefficients, same increasing penalty, two different penalty shapes.

w₁w₂w₃w₄w₅
Definition

Regularisation

Adding a penalty for large coefficients to the loss, so the model has to earn every bit of complexity it uses. It trades a little training accuracy for better generalisation.

Ridge: MSE + α Σ wᵢ²L2 — penalises squared size
Lasso: MSE + α Σ |wᵢ|L1 — penalises absolute size
Why the shapes differ

Squaring makes the penalty on a tiny coefficient almost nothing, so Ridge shrinks everything but kills nothing. The absolute value keeps pushing with the same force all the way to zero, so Lasso drives weak features exactly to zero and removes them.

2.2 · Boosting

XGBoost — each tree fixes the last one's mistakes

Definition

Boosting

Building models in sequence, where each new one is trained on what the current ensemble is still getting wrong. Errors shrink round by round.

Bagging versus boosting

A Random Forest grows many trees independently on random subsets and averages them — that reduces variance. Boosting grows trees one at a time, each fitted to the running residual — that reduces bias. Boosting usually scores higher and is easier to overfit.

Why it dominates tabular data

Handles non-linearity, interactions and mixed feature types without being asked; needs no scaling; copes with missing values natively. For a table of rows and columns it is the default strong baseline.

xgboost with sensible starting settings
from xgboost import XGBRegressor

xgb = XGBRegressor(
    n_estimators=400,      # how many trees
    learning_rate=0.05,    # how much each one contributes
    max_depth=5,           # how complex each tree may be
    subsample=0.8,         # rows sampled per tree
    colsample_bytree=0.8,  # features sampled per tree
    random_state=42,
)
xgb.fit(X_tr, y_tr)
The two dials that matter

learning_rate and n_estimators pull against each other: halve the rate, roughly double the trees. Lower rate with more trees is slower to fit and usually generalises better.

2.3 · Choosing

Pick the model your situation actually calls for

If…UseBecause
You must explain every predictionLinearCoefficients are the explanation
More features than you have rowsRidgeKeeps the fit stable when plain linear cannot
You suspect most features are noiseLassoZeroes them out for you
Features move togetherRidgeShares weight between them instead of picking wildly
You want the best score on a tableXGBoostUsually wins, given a little tuning
You have very little dataLinear / RidgeFewer parameters to overfit with
How to actually decide

Do not argue about it. Fit all of them with default settings, cross-validate, and put the numbers in a table. The argument resolves itself in about forty seconds of compute.

the deciding table, in one loop
from sklearn.model_selection import cross_val_score
import pandas as pd

rows = []
for name, m in models.items():
    cv = cross_val_score(m, X, y, cv=5,
                         scoring="neg_mean_absolute_error")
    rows.append({"model": name,
                 "MAE": -cv.mean(),
                 "std": cv.std()})

print(pd.DataFrame(rows).sort_values("MAE"))

Read the spread, not just the mean

A model averaging MAE 40,000 ± 2,000 is worth more than one averaging 38,000 ± 15,000. The second one is unreliable — on your particular test split it might be far worse.

3.1 · Metrics

Four numbers, four different questions

MAE = (1/n) Σ |yᵢ − ŷᵢ|Average error, in the target's own units. Robust to outliers
RMSE = √[ (1/n) Σ (yᵢ − ŷᵢ)² ]Same units, but large errors dominate it
R² = 1 − SS_res / SS_totShare of the variation explained. Unitless, comparable across datasets
MAE or RMSE?

If being wrong by RM 100,000 once is much worse than being wrong by RM 10,000 ten times, use RMSE — it punishes the big miss. If all errors cost the same per ringgit, use MAE. This is a business question, not a statistics question.

How to report it

Always give MAE alongside R². R² tells a technical reader how much structure you captured; MAE tells the client "we are typically off by about RM 38,000", which is the thing they can actually act on.

the full evaluation, one function
from sklearn.metrics import (
    mean_absolute_error, mean_squared_error, r2_score)

def report(model, X_te, y_te, name=""):
    p = model.predict(X_te)
    return {
        "model": name,
        "MAE"  : mean_absolute_error(y_te, p),
        "RMSE" : mean_squared_error(y_te, p) ** 0.5,
        "R2"   : r2_score(y_te, p),
    }

print(pd.DataFrame([report(m, X_te, y_te, n)
                    for n, m in models.items()]))

A negative R² is not a bug

It means your model does worse than simply predicting the mean every time. Usually a sign of leakage in reverse, a broken split, or features with no signal.

3.2 · Residuals

The residual plot tells you what the score cannot

Left: each red drop is one residual. Right: the same residuals plotted against x — this is the plot you actually read.

actual valuefitted lineresidual
Definition

Residual

The gap between what actually happened and what the model predicted: residual = y − ŷ. One per sample.

Why plot them

R² gives you one number for the whole model. The residual plot shows you where it is wrong. Those are completely different questions, and only the second one tells you what to fix.

PatternIt means
Random cloudGood — the model captured the structure
A curveReal relationship is non-linear; add a term or change model
Fanning outError grows with size; try predicting log(y)
ClumpsA group behaves differently; you may be missing a feature
3.3 · Mistakes

Four ways to produce a confident, wrong model

1 · Reporting the training score

model.score(X_train, y_train) is not a result. It is the model marking its own homework. Report test or cross-validated scores only.

2 · Extrapolating past the data

A model trained on 800–2,000 sq ft houses has no idea what a 9,000 sq ft one costs. Linear models will happily give you a confident number anyway; tree models will just repeat their edge value.

3 · Treating a coefficient as a cause

"Each bedroom adds RM 8,120" describes a correlation in your data. Adding a partition wall to create a bedroom will not add RM 8,120. Regression finds association, not causation.

4 · Ignoring the units

R² = 0.91 sounds excellent until MAE turns out to be RM 82,000 on a RM 400,000 house. Always convert the score back into the client's world before calling it good.

The habit that catches all four

Before you present any model, write one sentence in plain language: "On houses it has never seen, this model is typically off by RM X, and it is worst on Y." If you cannot fill in X and Y, you have not finished evaluating.

checking where it's worst
res = y_te - model.predict(X_te)

out = X_te.copy()
out["actual"]   = y_te
out["residual"] = res

# the 10 worst misses — look for what they share
print(out.reindex(res.abs()
        .sort_values(ascending=False).index).head(10))

The three sentences are the deliverable

Not the model, not the score — the sentences. That is what a client, a manager or an examiner actually reads, and writing them forces you to have understood your own result.
