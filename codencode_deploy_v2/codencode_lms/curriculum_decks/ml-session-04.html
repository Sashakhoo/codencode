What does a coefficient mean?

How much the prediction moves per one-unit rise in that feature, holding everything else fixed.

Ridge or Lasso?

Both penalise large coefficients. Ridge shrinks everything toward zero; Lasso drives weak features exactly to zero.

Why plot residuals?

A score tells you how wrong you are overall. Residuals tell you where — which is the part you can act on.

1.1 · Definitions

Classification predicts which class, not how much

Definition

Classification

A supervised task where the target is a category. The model outputs either a class label, or — more usefully — a probability for each class.

TypeClassesExample
Binary2Churn / stay · fraud / legitimate
Multi-class3+, one appliesWhich of 12 defect types
Multi-label3+, several applyTags on an article
The bit everyone skips

Most classifiers do not really output a class. They output a probability, and then somebody — usually a default you never looked at — compares it to 0.5. That 0.5 is a choice, and Module 2 is about choosing it deliberately.

predict vs predict_proba
model.predict(X_te)[:5]
# array([0, 0, 1, 0, 0])   ← already decided for you

model.predict_proba(X_te)[:5]
# array([[0.91, 0.09],    ← 9% chance of churn
#        [0.88, 0.12],
#        [0.34, 0.66],    ← 66%, flagged
#        [0.79, 0.21],
#        [0.52, 0.48]])   ← 48%, NOT flagged. Sure about that?

That last row is the whole session

A customer at 48% was one percentage point away from being flagged, and got treated exactly like one at 9%. Whether that is right depends entirely on what a missed churn costs you.

1.2 · Decision trees

A tree is a sequence of yes/no questions it worked out itself

Watch each split carve the space, and the tree grow beside it. Three splits, four regions, one answer each.

class Aclass Bsplit
Definition

Decision tree

A model that repeatedly splits the data on one feature at a time, choosing at each step the split that makes the resulting groups as pure as possible.

Gini = 1 − Σ pᵢ²0 = perfectly pure · 0.5 = a 50/50 mix in binary
How it picks a split

It tries every feature at every sensible cut point, measures how much purer the two resulting groups are, and keeps the winner. Then it repeats inside each group. No maths degree required — it is brute force with a scoring rule.

Why trees overfit alone

Left unchecked a tree keeps splitting until every leaf holds one sample — perfect on training data, useless on anything new. That is why we limit depth, and why we grow forests.

1.3 · Random Forest

Many mediocre trees, voting

Definition

Bagging

Training many models on random subsets of the rows and features, then averaging or voting. Individual models are weaker; the ensemble is far more stable.

Why randomness helps

One deep tree latches onto quirks of the particular rows it saw. Grow 300 trees, each on a different random sample with a different random subset of features to choose from, and those quirks disagree with each other and cancel out. What survives the vote is the real signal.

The practical upshot

A Random Forest is very hard to make badly. It handles non-linearity and mixed feature types, needs no scaling, and gives sensible results on the default settings. It is the right thing to try second, immediately after a baseline.

forest, and what it learned from
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=300,     # how many trees
    max_depth=None,        # let them grow; the vote protects you
    min_samples_leaf=2,   # but not down to single samples
    class_weight="balanced",  # see Module 2
    random_state=42, n_jobs=-1,
).fit(X_tr, y_tr)

# which features actually mattered
imp = pd.Series(rf.feature_importances_, index=X.columns)
print(imp.sort_values(ascending=False).head(8))

Read importances carefully

They tell you which features the forest used, not which ones cause the outcome. Two correlated features will split the credit between them, making both look half as important as either really is.

Build a tree by hand, then check it

Ten customers, three features, churn yes/no. You are the algorithm.

01Pick the one feature and cut point you think best separates churners from stayers.
02Split the ten rows on it. Count the classes in each side.

A decision tree is the only model you can fully reproduce with a pencil. Do it once and tree-based models — which is most of what wins on tabular data — stop being a black box.

2.1 · Confusion matrix

Four outcomes, and two of them are your problem

OutcomeMeansChurn example
True positiveFlagged, and it was realCaught a leaver — sent them an offer
True negativeNot flagged, correctlyLoyal customer, left alone
False positiveFlagged, but wrongWasted a discount on someone who was staying
False negativeMissed a real oneThey churned. Nobody noticed.
The two errors are not equal

A wasted RM 30 discount is annoying. A churned customer worth RM 2,000 a year is a real loss. When the two errors cost different amounts — they almost always do — a single accuracy figure has already thrown that information away.

the matrix, and a readable report
from sklearn.metrics import (
    confusion_matrix, classification_report)

pred = model.predict(X_te)

print(confusion_matrix(y_te, pred))
# [[2510   74]   ← TN  FP
#  [ 231  185]]  ← FN  TP

print(classification_report(y_te, pred))
#               precision  recall  f1-score
#   0 (stay)        0.92     0.97     0.94
#   1 (churn)       0.71     0.44     0.55   ← the real story

Read the minority row

That model is 90% accurate overall and catches 44% of churners. If you only ever looked at accuracy you would have shipped it and wondered why churn never improved.

2.2 · Precision & recall

Move the threshold — watch the trade-off happen

300 customers, 12% of them churners. The model's scores are fixed — only where you draw the line changes.

actually negativeactually positivethreshold
precision = TP / (TP + FP)Of everything I flagged, how much was real?
recall = TP / (TP + FN)Of everything real, how much did I catch?

Verdict

—

precision  —
recall     —
F1         —
accuracy   —

Slide it to 0.15: recall hits 100%, and precision collapses to 16%. The model now catches every churner and is wrong about five flags in six.

2.3 · Imbalance

When one class is rare, accuracy becomes a liar

Definition

Class imbalance

When one class vastly outnumbers the other — fraud, churn, disease, defects. The interesting class is almost always the rare one.

The 99% model that does nothing

1% of transactions are fraud. Predict "not fraud" every single time and you score 99% accuracy, catch zero fraud, and have built nothing. Accuracy rewards ignoring the minority class.

FixWhat it doesWatch out
class_weight="balanced"Makes minority errors cost more during trainingFree, try it first
Tune the thresholdMoves the decision line, no retrainingOften the biggest win
SMOTESynthesises new minority samplesOnly ever on the training split
Undersample majorityThrows away majority rowsYou lose real data
Collect moreActually fixes itSlow, and usually the right answer
Start with the cheap two

class_weight and threshold tuning cost nothing, need no extra libraries, and solve most real imbalance problems. Reach for SMOTE only when those two are not enough — and never apply it before the split, or you have leaked synthetic copies of test rows into training.

the cheap fixes, in practice
# 1. make minority mistakes expensive
rf = RandomForestClassifier(
    class_weight="balanced", random_state=42).fit(X_tr, y_tr)

# 2. choose the threshold on purpose
proba = rf.predict_proba(X_te)[:, 1]

from sklearn.metrics import precision_recall_curve
prec, rec, thr = precision_recall_curve(y_te, proba)

f1 = 2*prec*rec / (prec+rec+1e-9)
best = thr[f1[:-1].argmax()]
print(f"best F1 threshold: {best:.2f}")

pred = (proba >= best).astype(int)

But F1 is not automatically right either

F1 assumes precision and recall matter equally. For cancer screening recall matters far more; for sending an expensive offer, precision does. Optimise F1 only when you genuinely have no preference.

Hands-on · Module 2

Set a threshold you can defend

25 minutes · pairs

Set a threshold you can defend

Two scenarios, same model, same probabilities. Only the cost of being wrong changes.

01Scenario A — a churn offer costs RM 30; a lost customer costs RM 2,000. Which error is worse?
02Scenario B — the flag sends a customer to a 45-minute manual review by a human who is already busy.
03For each, pick a threshold and state the precision and recall it gives you.
04Write the sentence you would say to a manager to justify it.
05Compute the expected ringgit cost of each threshold and check it agrees with your instinct.
putting money on the errors
import numpy as np

COST_FP = 30      # wasted offer
COST_FN = 2000    # lost customer

for t in np.arange(0.1, 0.9, 0.05):
    pred = (proba >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_te, pred).ravel()
    cost = fp*COST_FP + fn*COST_FN
    print(f"{t:.2f}  FP={fp:4d}  FN={fn:4d}  cost=RM {cost:,}")

The answer will surprise them

With those costs the best threshold is usually far below 0.5 — around 0.2. It flags plenty of people who were staying, and that is correct, because a wasted RM 30 is 66 times cheaper than a missed churn.

3.1 · Boosting

XGBoost — the usual winner on tabular classification

Same idea as last week, different target

Boosting builds trees in sequence, each one trained on what the ensemble still gets wrong. For classification it is fitting the gradient of the log-loss rather than a residual in ringgit, but the intuition is unchanged: each round cleans up after the last.

xgboost for an imbalanced binary target
from xgboost import XGBClassifier

# ratio of negatives to positives — xgboost's imbalance dial
ratio = (y_tr == 0).sum() / (y_tr == 1).sum()

xgb = XGBClassifier(
    n_estimators=500,
    learning_rate=0.05,
    max_depth=4,
    subsample=0.8,
    colsample_bytree=0.8,
    scale_pos_weight=ratio,   # ← the imbalance fix
    eval_metric="logloss",
    random_state=42,
).fit(X_tr, y_tr)

proba = xgb.predict_proba(X_te)[:, 1]

scale_pos_weight is the one to remember

It is XGBoost's equivalent of class_weight="balanced". Set it to negatives ÷ positives and the model stops ignoring your rare class.

3.2 · Tuning

Four dials, in the order worth turning them

SettingDoesSensible range
learning_rateHow much each tree contributes0.01 – 0.3
n_estimatorsHow many trees100 – 1000
max_depthHow complex each tree may be3 – 8
subsampleRows sampled per tree0.6 – 1.0
Do not grid-search everything

A full grid over four settings is hundreds of fits for a gain you often cannot measure. Start with RandomizedSearchCV over a sensible range, run 30 candidates, and stop. Most of the improvement in a real project comes from features and the threshold, not from the fourth decimal of a learning rate.

a search that finishes before lunch
from sklearn.model_selection import RandomizedSearchCV

grid = {
    "n_estimators" : [200, 400, 800],
    "learning_rate": [0.02, 0.05, 0.1],
    "max_depth"    : [3, 4, 6],
    "subsample"    : [0.7, 0.85, 1.0],
}

search = RandomizedSearchCV(
    XGBClassifier(random_state=42, eval_metric="logloss"),
    grid, n_iter=30, cv=5,
    scoring="f1",      # NOT accuracy
    random_state=42, n_jobs=-1,
).fit(X_tr, y_tr)

print(search.best_params_)
print(f"best CV F1: {search.best_score_:.3f}")

Note the scoring argument

Leave scoring at its default and the search optimises accuracy — on imbalanced data it will happily hand you the model that predicts the majority class best.

3.3 · Putting it together

The order that actually produces a good classifier

01Split first. Stratify, so both splits keep the same class balance.
02Baseline: predict the majority class. Record its accuracy — this is what you must beat meaningfully.
03Fit a Random Forest with class_weight="balanced". Read the classification report.
04Fit XGBoost with scale_pos_weight. Compare on F1, not accuracy.
05Tune the threshold against the real cost of each error type.
06Report precision and recall on the minority class, at the threshold you chose.
Steps 5 and 6 are where the value is

Steps 1–4 are the part everyone does. Choosing a threshold against real costs, and reporting the minority-class numbers honestly, is the part that separates a model that gets deployed from one that gets quietly abandoned.

stratify — the split detail that matters here
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y,
    test_size=0.2,
    stratify=y,          # ← keeps 12% churn in BOTH splits
    random_state=42,
)

print(y_tr.mean(), y_te.mean())   # should match

Without stratify

On a rare class a random split can easily hand your test set half the usual proportion of positives — and then your recall figure is measuring noise.

Code Lab — a classifier you would actually deploy

30 minutes · solo

Code Lab — a classifier you would actually deploy

01Stratified split. Confirm the class balance matches on both sides.
02Majority-class baseline — write down its accuracy, and its recall (it will be zero).
03Random Forest with class_weight='balanced'. Full classification report.
04XGBoost with scale_pos_weight. Compare F1 against the forest.

06Final report: confusion matrix, precision, recall and F1 at your chosen threshold.
the honest final report
best_t = 0.22   # whatever your sweep chose
pred = (proba >= best_t).astype(int)

tn, fp, fn, tp = confusion_matrix(y_te, pred).ravel()

print(f"threshold  {best_t}")
print(f"caught     {tp} of {tp+fn} churners  ({tp/(tp+fn):.0%})")
print(f"wasted     {fp} offers")
print(f"cost       RM {fp*30 + fn*2000:,}")
print(f"vs doing nothing: RM {(tp+fn)*2000:,}")

End with that last line

"Doing nothing costs RM 832,000 a year. This model costs RM 291,000." That is the sentence that gets a model deployed — not an F1 score.
